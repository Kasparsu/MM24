## 🗂️ Topics Covered

> 🔗 The morning ended with `/api/posts` in place but no real data on the page. This lesson
> made one Laravel action answer with HTML or JSON depending on who asks, put the real posts
> into Nuxt UI's blog cards (with an appended `snippet` attribute for a short text), and added
> working pagination that remembers the page in the URL.

### 1. 🔀 One action, HTML or JSON

`/api/posts` pointed to `PublicController@index`, so it returned the same thing as the
front page: the rendered `welcome` view. We still want that view for the browser, but the
frontend needs data. Laravel's request can tell what the client is willing to accept:

```php
    public function index() {
        $posts = Post::with('images', 'user', 'tags')->withCount('comments', 'likes')->latest()->paginate(16);
        if(request()->acceptsHtml()){
            return view('welcome', compact('posts'));
        }
        return $posts;
    }
```

Returning the paginator straight from the action makes Laravel send it as JSON. (A quick
test first was a `return $posts;` above the view: `return` ends the function, and the editor
greys out the unreachable code below it.)

To read that JSON comfortably in the browser, the **JSON Viewer** extension
(<https://chromewebstore.google.com/detail/json-viewer/gbdbademeighmnbliehmnoifmabbedbp?hl=en>)
folds it into a tree with themes to choose from. It showed a `data` list of 16 posts, each
with its title, body, images, user and tags.

### 2. 📨 The Accept header

The browser's network tab shows why this works: a normal page load sends a very specific
`Accept` header listing `text/html` first. The catch was that `$fetch` from Nuxt also ended
up with HTML, because by default it accepts anything. The fix is on the frontend side, to say
it wants JSON only:

```ts
  let data: any = await $fetch('http://localhost:8000/api/posts', {
    query: {
      page: p,
    },
    headers: {
      accept: 'application/json',
    }
  });
```

Now the browser gets the view and the frontend gets JSON from the same address. (The view
part could be removed entirely later, it stays for now.) `$fetch` returns a **promise**, so
`await` waits for the answer and gives the data itself.

### 3. 🧾 Laravel fields to Nuxt UI props

`UBlogPost` expects `title`, `description`, `image`, `date`; Laravel gives `title`, `body`,
`images`, `created_at`. So each post is mapped by hand, and the Faker posts from the morning
were removed:

```ts
  for(post of data.data) {
    posts.value.push({
      title: post.title,
      description: post.snippet,
      image: post.images[0]?.path,
      date: post.created_at,
    });
  }
```

- **`images[0]?.path`**: a post has a list of images and the card shows one. Posts without
  any images have no `[0]`, and `?.` (optional chaining) gives `undefined` instead of an error.
- **`snippet`** instead of `body`: whole bodies made the cards very long. The `Post` model
  already had a `snippet` accessor (the first paragraph of the body), but accessors are not in
  the JSON unless you **append** them:

```php
use Illuminate\Database\Eloquent\Attributes\Appends;
...
#[Appends(['snippet'])]
class Post extends Model
```

The `$appends` docs also show `->append()` on a single result, but adding it on the model
means every post sent as JSON has it. After a refresh the JSON had `snippet` and the cards
were short.

The `app.vue` menu still had the Nuxt UI docs' example links, pointing to pages we do not
have; they were commented out, and the layout was wrapped in `<ClientOnly>` for now.

### 4. 📄 Pagination with UPagination

Nuxt UI has a `UPagination` component. To draw it, it needs to know how many posts there are
in total, but the response did not say. The reason: the controller used `simplePaginate`,
which only knows "previous" and "next". Switching back to `paginate(16)` (see the controller
above) brings `total`, `per_page` and `current_page` into the JSON.

The fetch went into a function, so it can be called again for another page:

```ts
const posts = ref<BlogPostProps[]>([]);
let page = ref(0);
let total = ref(0);
let perPage = ref(0);
let post: any;
let route = useRoute();
await getPosts(Number(route.query.page) || 1);

async function getPosts(p: Number){
  // $fetch as above
  page.value = data.current_page;
  total.value = data.total;
  perPage.value = data.per_page;
  posts.value = [];
  // the for loop from section 3
}
```

```vue
<UPagination @update:page="getPosts" :to="to" v-model:page="page" :items-per-page="perPage" :total="total" show-edges :sibling-count="2" />
```

Things learned on the way:

- **The total alone is not enough.** With only `total` the component showed a wrong number of
  pages until `items-per-page` was set too (16 per page, 63 pages).
- **`@update:page`** fires when a page number is clicked, and the event value is that number,
  so `getPosts` can be the handler directly.
- **Name clash**: the function's parameter was first called `page`, the same as the `page`
  ref outside, so it was renamed to `p`.
- **Empty the list first.** Without `posts.value = []` every click pushed the new posts after
  the old ones and the page just grew longer.
- **`show-edges`** shows the first and last page, **`sibling-count`** how many numbers sit
  next to the current one.
- **Query parameters**: `?page=` could be glued onto the URL as a string, but `$fetch`'s
  `query` option is tidier, especially once there are more parameters.

### 5. 🔗 The page number in the URL

After a refresh the page always jumped back to page 1. `UPagination` takes a `to` function
that turns a page number into a link, so clicking a number also changes the address:

```ts
function to(page: number) {
  return {
    query: {
      page
    }
  }
}
```

On load, `useRoute().query.page` reads the number back. It comes as text (or is missing on
the front page), so `Number(route.query.page) || 1` makes it a number and falls back to the
first page. Now `/?page=5` survives a refresh.

### 6. 🤔 Why is this so complicated?

A fair question at the end. Two reasons: the Nuxt UI components were not made for Laravel's
data, so a lot has to be mapped (title, snippet instead of description, images, dates that
the component formats itself), and the frontend has to be taught how Laravel's pagination
works. The hard part is writing this the first time. The same pattern works for every other
list in the blog, so written a bit smarter once, it can be reused. More of it next time.

## ✅ Takeaways

1. **`request()->acceptsHtml()`** lets one action return a view to browsers and JSON to the frontend.
2. **Send `accept: 'application/json'`** from `$fetch`, or Laravel may answer with HTML.
3. **Map the fields**: Laravel's `body`, `images`, `created_at` are not Nuxt UI's `description`, `image`, `date`.
4. **`#[Appends(['snippet'])]`** puts an accessor into the model's JSON.
5. **`?.`** avoids errors on posts without images.
6. **`paginate`, not `simplePaginate`**, when the frontend needs the total.
7. **Empty the array** before filling it with a new page.
8. **Keep the page in the URL** with the `to` function and read it back from `route.query.page`.
