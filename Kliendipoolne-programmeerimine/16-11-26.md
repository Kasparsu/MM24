### 2. 🪟 Modal, dialog, modaalaken

The form asks whether a framework has a **modal**. A student asked what that is, and what the
right Estonian word would be: *modaalaken* (modal window).

A modal is the small window that opens on top of everything else and darkens the rest of the
page, so the user deals with it before going on. Last year the class built one with
JavaScript for opening pictures. Instagram does the same when you click a photo: the large
picture with the comments beside it is a modal. Frameworks also call it a dialog, a lightbox or
a popup, but the idea is the same.

The name "dialog" is no accident: HTML now has a `<dialog>` element of its own
(<https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog>). The MDN page's
"Edit profile" example opens over a darkened page with plain HTML and a couple of JavaScript
convenience methods (`showModal()` to open, `close()` to close). Plenty is possible without any
library, even if many projects still use their framework's component.

### 3. 📦 What a build produces

Next a look at what happens to all the `.vue` files when the site goes live. During
development the dev server serves them, but a real deployment needs the end result: the
**build** takes all source files and bundles them into the final JavaScript and CSS files
(plus whatever else the site needs). The smaller that bundle, the faster the page loads, which
is also one thing to compare between component frameworks.

Two ways to build a Nuxt project, both from the `package.json` scripts:

- **`build`** makes a production version in `.output/` that runs with its own Node server.
- **`generate`** makes **static** pages: plain HTML, JS and CSS files in `.output/public` that
  need no server-side code at all and can be put on any static web host.

Looking into `.output/public` after `generate` showed the HTML for the pages and a handful of
JavaScript and CSS files, all small for now since the demo pages have almost no content.

## ✅ Takeaways

1. **Framework form** due 20.11: at least 5 frameworks, each with the same questions, then a reasoned pick.
2. **A modal (modaalaken)** is a window on top of a darkened page; frameworks call it dialog, lightbox or popup too.
3. **HTML has `<dialog>`** built in, opened with `showModal()` and closed with `close()`.
4. **`build`** makes a server version, **`generate`** makes static files that need no server.
5. **Bundle size matters**: smaller JS and CSS loads faster.
