### 1. 📤 Uploading several images at once

The file input gets the `multiple` attribute, and the file picker lets you select many files
(hold Ctrl to pick them one by one, or Shift to select a whole range). But after submitting,
only one file reached the controller. A form field named `image` holds one value; with several
files under the same name, the last one wins. To send many values under one name, the name ends
in `[]`, and PHP turns them into an array:

```html
<input name="images[]" type="file" multiple accept="image/*" class="file-input w-full @error('images.*') file-input-error @enderror"/>
@error('images.*')
    <p class="label text-error">{{$message}}</p>
@enderror
```

Since there are now many pictures, the name became plural too. The validation rule changes with
it: `image` would check the whole array, which is not an image. `images.*` ("dot star") means
"every element of the `images` array", and the error lookup in the view uses the same key:

```php
return [
    'title' => 'required',
    'body' => 'nullable',
    'images.*' => 'image',
];
```

In `PostController@store`, the single-file code from yesterday became a loop over all the
uploaded files. Each one is stored, gets its URL, and is saved as an `Image` attached to the post:

```php
foreach($request->file('images') as $file) {
    $image = $file->store('', ['disk' => 'public']);
    $url = Storage::url($image);

    $image = new Image();
    $image->path = $url;
    $image->post()->associate($post);
    $image->save();
}
```

A post with several pictures saved and showed them in the carousel. (Note: yesterday's `if`
around the upload went away in this change. When no file is chosen, `file('images')` is `null`,
so a post without pictures fails to save. This was fixed on 23.10 in commit `a4f297c` with
`foreach($request->file('images') ?? [] as $file)`: the `?? []` loops over an empty list when
no files were sent.)

### 2. 🧱 A Comment model with all its classes

A post can now also have comments. Artisan generated everything for the new model in one go:
the `Comment` model, the migration, `CommentFactory`, `CommentSeeder`, `CommentPolicy`, a resource
`CommentController` and the two form requests `StoreCommentRequest` and `UpdateCommentRequest`.
Most of them are empty stubs for now; the controller and the store request come back in the
homework.

The data starts in the migration. A comment needs its text, and an empty comment makes no sense,
so `body` is a `text` column that is **not** nullable. Then the question of what a comment is
attached to: the post it is written under, and the user who wrote it. A post so far belonged
only to a user, and an image only to a post. A comment has both foreign keys, built the same way
as before:

```php
Schema::create('comments', function (Blueprint $table) {
    $table->id();
    $table->text('body');
    $table->foreignIdFor(User::class)->constrained()->cascadeOnDelete();
    $table->foreignIdFor(Post::class)->constrained()->cascadeOnDelete();
    $table->timestamps();
});
```

`cascadeOnDelete()` means deleting a user or a post also deletes its comments.

### 3. 🏭 Factory and seeder: a pile of comments

The factory only fills what is not a relationship: a short fake sentence and the dates. The post
and the user are set by the seeder. To make the data look real, the creation date is random, and
about one comment in ten has been "edited" up to three days later (`rand(0,9)` is `0` only one
time in ten; otherwise the update time equals the creation time):

```php
$created = Carbon::create(fake()->dateTimeBetween());
$updated = fake()->dateTimeBetween($created, Carbon::create($created)->addDays(3));
if(rand(0,9)){
    $updated = $created;
}

return [
    'body' => fake()->sentence(),
    'created_at' => $created,
    'updated_at' => $updated,
];
```

The seeder follows the same pattern as the posts seeder: load only the `id` column
of users and posts once, then for every post `make()` (not `create()`) between zero and ten
comments, give each one a random user and save it:

```php
$users = User::select('id')->get();
$posts = Post::select('id')->get();
foreach($posts as $post) {
    $comments = Comment::factory(rand(0,10))->make(['post_id' => $post->id]);
    foreach($comments as $comment) {
        $comment->user_id = $users->random()->id;
        $comment->save();
    }
}
```

`make()` builds the models without saving, so the user can be filled in before the row hits the
database (the foreign key would reject a comment without one). Asked to guess how many comments
that makes: 1000 posts times five on average, roughly 5000, and the table after
`php artisan migrate:fresh --seed` agreed. The seeder is called last in `DatabaseSeeder`, after
users and posts exist:

```php
$this->call(UserSeeder::class);
$this->call(PostSeeder::class);
$this->call(ImageSeeder::class);
$this->call(CommentSeeder::class);
```

### 4. 🔗 Relationships both ways

A comment belongs to a post and to a user, and both of those have many comments. The same two
methods go on both sides, as was done for posts and users:

```php
// Comment.php
public function user() {
    return $this->belongsTo(User::class);
}

public function post() {
    return $this->belongsTo(Post::class);
}
```

```php
// Post.php and User.php
public function comments() {
    return $this->hasMany(Comment::class);
}
```

### 5. 👀 Showing the comments under a post

The single post page (`post.blade.php`) gets a heading and a loop over `$post->comments`. Each
comment is a small daisyUI card with its text, the author's name through the `user` relationship,
and the "5 minutes ago" style date with `diffForHumans()` from Monday's lesson:

```html
<h1>Comments:</h1>
@foreach($post->comments as $comment)
    <div class="card bg-base-300 shadow-sm mt-2">
        <div class="card-body">
            <p>{{ $comment->body }}</p>
            <span class="text-base-content/70">{{ $comment->user->name }}</span>
            <span class="text-base-content/70">{{ $comment->created_at->diffForHumans() }}</span>
            <div class="card-actions justify-end"></div>
        </div>
    </div>
@endforeach
```

Opening a few posts showed the comments nicely under each one, but in an odd order: nothing sorts
them yet, so they come out in the order they were seeded, not by date. The design could also be
nicer, which is left for later.

### 6. 🏠 Homework (due 28.10): adding a comment

Details in the Teams assignment *Add ability to comment to blog project*. Comments can be read
but not written. The steps are written into the code itself, as a Blade comment in
`post.blade.php`:

```html
{{--
    1. add form here to add comment use @auth to only show when logged in (look how posts/create.blade.php is done)
    2. add route that takes route parameter for post (id) and use CommentController store method
    3. Fix StoreCommentRequest to allow requests (authorize return true) and add validation to require body field
    4. Add Post $post to store method in CommentController and add logic to create new Comment and fill its body and associate post and user (look at PostController store method)
--}}
```

In short:

1. **Form**: a `textarea name="body"` with `@csrf`, `@error('body')` and `old('body')`, shown only
   to a logged in user (`@auth ... @endauth`), like `posts/create.blade.php`.
2. **Route**: a POST route with the post as a route parameter, for example
   `/post/{post}/comments` named `comments.store`, with the `auth` middleware, going to
   `CommentController@store`.
3. **Validation**: in `StoreCommentRequest`, `authorize()` returns `true` (the generated one
   returns `false` and blocks every request) and `body` is `required`.
4. **Saving**: `store` takes `Post $post`, creates a `Comment` from the validated body, and attaches
   the post and the logged in user with `associate()`, like `$post->user()->associate(Auth::user())`
   in `PostController`. If you use `new Comment($request->validated())`, add
   `protected $fillable = ['body'];` to the model.
5. **Redirect** back to the same post: `redirect()->route('post', $post)`.

Before handing in, check: logged out there is no form, an empty comment shows an error and keeps
the form, and a new comment appears under the post with your name and time. Hand in the link to
your mm24blog repository (the commit with the feature).

## ✅ Takeaways

1. **Many files under one name need `[]`** (`name="images[]"`) plus the `multiple` attribute; without the brackets only the last file arrives.
2. **`images.*` validates every element** of an array field, and `@error('images.*')` shows its message.
3. **A comment has two foreign keys**: the post it is under and the user who wrote it, both with `cascadeOnDelete()`.
4. **Seed with `make()`, fill the relationships, then `save()`**, and load only the ids you need once, not per row.
5. **Relationships go on both sides**: `belongsTo` on the comment, `hasMany` on the post and the user.
6. **A generated form request starts with `authorize()` returning `false`**: fix it, or every request is refused.
