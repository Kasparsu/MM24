## 🗂️ Topics Covered

> 🖼️ Yesterday every post got at most one image. Today a post can have many, shown in a
> daisyUI carousel, and the post form gets a file field so users can upload their own picture.
> Uploading leads to the `public` disk, `storage:link` and `Storage::url()`, and finally to the
> question of how to make sure the upload really is an image.

### 1. 🔁 From one image to many

The client changes their mind: a post should have several pictures. Because the image already
lives in its own table, the change is small. In the migration the foreign key loses `unique()`,
so many image rows can point at the same post:

```php
$table->foreignIdFor(Post::class)->constrained()->cascadeOnDelete();
```

In the `Post` model the relationship becomes plural and `hasMany` instead of `hasOne`:

```php
public function images() {
    return $this->hasMany(Image::class);
}
```

A side note from the demo: `$post->images` (no brackets) runs the query and gives a collection,
while `$post->images()` gives the query itself, which you can still modify (for example ask for
only the first row) before it runs.

The seeder used to give 9 posts out of 10 one image. Now each post gets between zero and five:

```php
Image::factory(rand(0,5))->create(['post_id' => $post->id]);
```

After `php artisan migrate:fresh --seed` there were about 2500 images for 1000 posts, roughly
2.5 per post.

### 2. 🎠 A carousel for several images

daisyUI has a carousel component
(<https://daisyui.com/components/carousel/#carousel-with-full-width-items>). The example has a
`carousel-item` per picture; we keep one and repeat it with `@foreach`. The post card now asks
how many images there are: one image is shown as before, more than one go in the carousel:

```html
@if ($post->images->count() === 1)
    <figure>
        <img src="{{ $post->images->first()->path }}" />
    </figure>
@elseif($post->images->count() > 1)
    <div class="carousel rounded-box">
       @foreach($post->images as $image)
           <div class="carousel-item w-full">
               <img src="{{ $image->path }}" class="w-full" />
           </div>
       @endforeach
    </div>
@endif
```

The fixed width class from the daisyUI example was dropped so the pictures fill the card. The
carousel is pure CSS, no JavaScript: on a phone you swipe and it works great, on a desktop you
have to scroll sideways (middle click and drag, or a horizontal scroll). Arrows or buttons would
need some JavaScript (for example Alpine), which was left for later.

### 3. 📤 A file field in the post form

So far a new post never had a picture. The create form gets a new fieldset, built from the
title one, with a daisyUI file input (<https://daisyui.com/components/file-input/>):

```html
<fieldset class="fieldset">
    <legend class="fieldset-legend">Image</legend>
    <input name="image" type="file" class="file-input w-full @error('image') file-input-error @enderror"/>
    @error('image')
        <p class="label text-error">{{$message}}</p>
    @enderror
</fieldset>
```

A file field cannot be refilled with `old()` after a failed validation (the browser will not
let a page pick a file for you), so that part was left out.

The easy thing to forget: a form only sends files if it says so. Without `enctype` the
controller gets just the file name.

```html
<form action="{{route('posts.store')}}" method="POST" enctype="multipart/form-data" class="card bg-base-300 shadow-sm w-2/3 mx-auto p-3">
```

### 4. 💾 Storing the upload

In `PostController@store`, `$request->file('image')` returns an `UploadedFile` object (a quick
`dd()` showed its original name, MIME type, size and the temp file). Its `store()` method saves
it with a random name and returns the path:

```php
$image = $request->file('image')->store('', ['disk' => 'public']);
$url = Storage::url($image);
```

The `public` disk is `storage/app/public`. The random name means two users uploading `cat.jpg`
do not overwrite each other.

### 5. 🔗 `storage:link` and `Storage::url()`

Files in `storage/app/public` are still not reachable from the web, only the `public` folder
is. Laravel's answer is one command:

```
php artisan storage:link
```

It creates `public/storage` as a **symbolic link** (symlink) to `storage/app/public`. Nothing
is copied: it is the same folder visible in two places. Upload a picture and it appears in
both; delete a file in one and it is gone from the other too.

The link is not committed to git, so every fresh clone needs the command once. That is why it
became a step in the README:

```
11. `php artisan storage:link`
12. run laravel `composer run dev`
```

To turn the stored file name into an address the browser can load, `Storage::url()` (from
`Illuminate\Support\Facades\Storage`, not one of the other classes called Storage) builds the
`/storage/...` URL.

### 6. 🧩 Saving the Image row

The post has to be saved first so it has an id. Then a new `Image` gets the URL and is attached
to the post, the same `associate()` used for the post's user:

```php
$image = new Image();
$image->path = $url;
$image->post()->associate($post);
$image->save();
```

The new post showed up on the front page with its picture.

### 7. 🛡️ Is it really an image?

Nothing stopped us from uploading something that is not a picture. In the demo a `.exe` went
through, was stored, and opening its URL downloaded the program. Two fixes:

**`accept` on the input** filters the file picker:

```html
<input name="image" type="file" accept="image/*" class="file-input w-full @error('image') file-input-error @enderror"/>
```

`image/*` is a MIME type pattern (<https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/MIME_types>):
`application/pdf`, `application/zip`, `text/plain`, `text/javascript`, `video/mp4` and so on.
The picker now shows only folders and images, which helps someone with eight years of mixed
files in Downloads. But it is **convenience, not security**: anyone can switch the filter to
"all files" or send the request without the browser.

![Inigo](https://api.memegen.link/images/inigo/accept=''image~s*''_is_a_security_check/I_do_not_think_it_means_what_you_think_it_means.png)

**Validation on the server** is the real check. `StorePostRequest` gets an `image` rule,
built into Laravel:

```php
return [
    'title' => 'required',
    'body' => 'nullable',
    'image' => 'image',
];
```

Testing without a picture found one more bug: `$request->file('image')` is `null` when nothing
was uploaded, and calling `store()` on `null` crashes. The image part of `store` went inside an
`if`:

```php
if($request->file('image')) {
    $image = $request->file('image')->store('', ['disk' => 'public']);
    $url = Storage::url($image);

    $image = new Image();
    $image->path = $url;
    $image->post()->associate($post);
    $image->save();
}
```

Now a post without a picture saves, a post with a picture saves, and a non-image gets the
"must be an image" error under the field. Uploading several images at once did not fit into
this lesson.

## ✅ Takeaways

1. **One to many is a small change** when the images already have their own table: drop `unique()`, `hasOne` becomes `hasMany`.
2. **daisyUI's carousel is CSS only**: great on phones, awkward with a mouse.
3. **File uploads need `enctype="multipart/form-data"`** on the form.
4. **`store()` on the `public` disk + `php artisan storage:link` + `Storage::url()`** makes uploads visible on the web. The symlink is not in git, so it is a setup step.
5. **`accept="image/*"` is for convenience, the `image` validation rule is for security.**
6. **An optional file can be `null`**: check before calling methods on it.
