### 2. 🧱 Cards in a grid

The posts were one long column of cards. Four next to each other would look better. Tailwind's
layout section has both Flexbox and Grid utilities
(<https://tailwindcss.com/docs/grid-template-columns>).

With flex the cards first ran off the side of the page in one row. `flex-wrap` lets them move to
the next row, but only if they are narrower than the page, and limiting each card to `w-1/4`
still did not fit four in a row: the `gap` between them also takes space out of the same width.
It can be fixed, but it is a headache.

Grid was invented for exactly this. One wrapper `div` around the `@foreach` says how many
columns there are, and the cards no longer need a width at all:

```html
<div class="grid grid-cols-4 gap-2">
    @foreach ($posts as $post)
        <div class="card bg-base-100 shadow-sm">
```

The heading stays outside the grid, so it is not squeezed into the first cell. `gap-2` is now
counted in by the grid itself, and the `my-2` margin on the cards could go.

![Grid](https://api.memegen.link/images/khaby-lame/flex--wrap,_w--1~s4_and_a_gap_that_does_not_fit/grid_grid--cols--4_gap--2.png)

### 3. 🎨 daisyUI themes

daisyUI comes with many themes, but only a light and a dark one are built by default. All of
them can be switched on in the plugin settings in `resources/css/app.css`
(<https://daisyui.com/docs/themes/#enable-all-themes>):

```css
@plugin "daisyui" {
  themes: all;
}
```

Which theme is used is chosen with a `data-theme` attribute. It can be put on any element, so
only one section of a page gets a theme
(<https://daisyui.com/docs/themes/#how-to-use-a-theme-only-for-a-section-of-a-page>), or on
`<html>` in the layout for the whole site:

```html
<html lang="en" data-theme="dracula">
```

Pick whichever theme you like. A theme switcher for the users can come later.

On a dark theme the cards almost disappeared: `bg-base-100` is the page background colour
itself, and only the shadow showed where a card was. The base colours come in levels, `100`,
`200` and `300`, each a little darker, so the cards became `bg-base-300`. All the colour names
daisyUI themes define are listed at
<https://daisyui.com/docs/colors/#list-of-all-daisyui-color-names>.

![Themes](https://api.memegen.link/images/kombucha/The_default_white_page/data--theme=''dracula''.png)

### 4. 🔢 Not all thousand posts at once

The home page still shows every post. On our own computer, with one user and a local
database, it is quick, but in reality it is slow to query and slow to load, and nobody can find a
particular post by scrolling through a thousand.

A reminder from SQL: `LIMIT 3` at the end of a `SELECT` returns only three rows, and
`OFFSET 6` skips six first, so together they give rows 7, 8 and 9.

Laravel's query system is much more capable than the one we wrote in learnphp, and has the same
thing. But `Post::limit(16)` passed straight to the view crashed in Blade. `dd()` (dump and die,
built into Laravel) showed why: it is not a list of posts but a **query builder**. Laravel cannot
know whether we want to add more to the query (sorting, conditions), so it waits until we say we
are done. `get()` finishes the query and returns the results.

![Query builder](https://api.memegen.link/images/inigo/You_keep_calling_limit()_and_expecting_posts/I_do_not_think_it_returns_what_you_think_it_returns.png)

`take()` and `skip()` are friendlier names for the same `limit` and `offset`. A number divisible
by four (8, 12, 16, 20) keeps the last row of the grid full.

### 5. 🔗 The page number from the address bar

Query parameters do not need a form: anyone can type `/?page=2` into the address bar. In
learnphp we read them from `$_GET`. Superglobals have a big problem: they are global and
**writable**. A large framework runs through dozens of files before our controller (Laravel's
error page lists them all, deep in `vendor`), and if anything along the way overwrites a value,
good luck finding where.

Laravel reads them once at the start into a `Request` object, which can be read but not changed.
It can be had with the `request()` helper, or simply by asking for it as a parameter: Laravel
uses **reflection** to read what the controller method needs and passes it in.

Which posts belong to which page? Page 1 skips 0, page 2 skips 16, page 3 skips 32: one minus
the page, times the page size. The comment stayed in the code:

```php
public function index(Request $request) {
    $perPage = 16;
    $page = $request->query('page');
    // 1 => 0 ; 2 => 16 ; 3 => 32 ; 4 => 48; => 5 => 64
    $skip = ($page - 1) * $perPage;
    $posts = Post::take($perPage)->skip($skip)->get();
    return view('welcome', compact('posts'));
}
```

A tip: when a site only gives you "next" and "previous" buttons, look at the address bar. Often
the page is a parameter there, and you can jump straight where you want.

![By hand](https://api.memegen.link/images/bihw/Working_out_skip_from_the_page_number_by_hand/But_it's_honest_work.png)

### 6. ↩️ Undoing a commit: `git reset --soft`

A commit got a badly typed message. As it was not pushed yet, it was undone with:

```
git reset --soft HEAD~1
```

`--soft` moves back one commit but **keeps the changes** in the files, as if the commit was never
made. `--hard` would throw the changes away too (git still keeps them somewhere, but you do not
want to go looking). Once a commit is pushed, rewriting it would also need a force push.

### 7. 📚 `paginate()`

Nobody wants to write that logic every time, and Laravel does not make us:

```php
public function index() {
    $posts = Post::paginate(16);
    return view('welcome', compact('posts'));
}
```

`paginate()` reads the `page` parameter from the request itself and does the maths. Without an
argument it gives 15 per page, which is why the first try showed 15 posts. One line in the view
prints the page links:

```html
{{ $posts->links() }}
```

### 8. 🧩 Publishing and restyling the pagination view

The links came out in plain Tailwind and knew nothing about daisyUI's themes. The view can be
customised (<https://laravel.com/framework/docs/pagination#customizing-the-pagination-view>):

```
php artisan vendor:publish --tag=laravel-pagination
```

copies Laravel's pagination views from `vendor` (which we must not change) to
`resources/views/vendor/pagination` (which we may): Bootstrap 3, 4 and 5, Semantic UI, Tailwind
and the "simple" versions of each. The Tailwind one is used by default. Going through it:

- `hasPages()`: if everything fits on one page, show nothing.
- `onFirstPage()`: on page one the "previous" button is disabled, otherwise it links to
  `previousPageUrl()`. `hasMorePages()` and `nextPageUrl()` do the same at the end.
- `$elements`: a string element is the `...` separator, an array element is a set of page
  numbers with their URLs. The current page is shown but is not a link.
- The whole thing is there twice: a short version for small screens and the full one.
- Texts go through `__('pagination.previous')`: **translation strings**. If a client later wants
  the site in English and Russian too, adding a language file is enough, instead of going
  through forty views. A little extra work now saves a lot later.

The long Tailwind class lists became daisyUI classes, for example the disabled "previous" button:

```html
<button class="btn btn-outline btn-disabled" disabled>
    {!! __('pagination.previous') !!}
</button>
```

`btn-disabled` only makes it **look** disabled; the `disabled` attribute actually stops the
button working. The grey text (`text-gray-...`) was unreadable on a dark theme, so it became
`text-base-content`, a theme colour that changes with the theme. Hard coded colours do not.

At first the new classes did nothing. Tailwind only builds the classes it finds in the files it
scans, and the pattern in `app.css` only looked at one folder level. `**` makes it look in every
folder below:

```css
@source '../../storage/framework/views/**/*.php';
```

### 9. ♿ Arrows and `aria-*` attributes

Instead of the SVG icons the buttons got Unicode arrows: lists of them are on sites like
<https://unicode-explorer.com/list/arrows>, pick your favourite (an icon font or SVG files are
also fine). The page buttons were grouped with daisyUI's `join`:

```html
<button class="btn btn-disabled" disabled aria-disabled="true" aria-label="{{ __('pagination.previous') }}" aria-hidden="true">
    🢔
</button>
```

The `aria-*` attributes from the original were kept on purpose. They do nothing visible, but
screen readers use them:

- `aria-label` is what is read out instead of the content. A screen reader would otherwise read
  the arrow's Unicode name, or nothing.
- `aria-disabled` tells that the button cannot be used.
- `aria-hidden` makes the reader skip it altogether: a button that does nothing need not be
  announced.

Many apps are web pages in a frame, and the same attributes work on phones. Two videos show how
blind people actually use them: <https://www.youtube.com/watch?v=wueLXCbm_KY> (VoiceOver and
Braille screen input) and <https://www.youtube.com/watch?v=qdB8SRhqvFc> (ARIA and accessibility
APIs). More on MDN: <https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA>. Even if
you do not yet know where to put them yourself, never delete them from an example just because
they seem to do nothing: that only makes life harder for people whose life is hard enough.

![aria](https://api.memegen.link/images/stop-it/Deleting_aria--label_because_nothing_changes_on_screen/Stop_it._Get_some_help..png)

The rest of the view (the page numbers and the "next" button) was left for the next lesson.

## ✅ Takeaways

1. **Grid for grids**: `grid grid-cols-4 gap-2` on a wrapper, no widths on the cards.
2. **`themes: all` and `data-theme`**; use theme colours (`bg-base-300`, `text-base-content`), not fixed ones.
3. **A query is a builder until `get()`**; `take`/`skip` are `limit`/`offset`.
4. **No superglobals**: Laravel gives a read-only `Request`, injected into the controller.
5. **`git reset --soft HEAD~1`** undoes a commit and keeps the code.
6. **`paginate(16)` and `links()`**; `vendor:publish` to customise the view.
7. **Keep the `aria-*` attributes.** Screen readers depend on them.
