## 🗂️ Topics Covered

> 🛡️ Showing the post's paragraphs properly turns into a lesson on XSS and on what Blade's
> `{{ }}` protects us from. Then the links get names so a URL can change in one place, the texts
> go through translation strings, and the admin side of the blog starts with a table of posts.

### 1. ↩️ Newlines in the post body

The single post page showed the body as one block: the empty lines between paragraphs were gone.
They are in the database, but HTML treats a newline like any other whitespace. PHP has a function
just for this, `nl2br()`, which puts a `<br>` before every newline.

But `{{ nl2br($post->body) }}` showed the `<br>` tags as text. Blade's `{{ }}` runs everything
through `htmlspecialchars()`, which turns `<`, `>`, quotes and `&` into HTML entities (`&lt;`
and so on), so the browser shows them instead of treating them as tags.

`{!! !!}` prints without that protection. The exclamation marks are a warning: you are on your
own here.

### 2. 💉 Why `{{ }}` escapes: XSS

To show why, a post's body was edited in the database (there is no edit form yet) to contain a
`<script>` tag. With `{!! !!}` the script **ran** in the browser of everyone who opened the post.
That is **XSS**, cross-site scripting: if someone can get their text into our database and we
print it raw, they can run their JavaScript on our page, for every visitor. Script tags are not
the only way to do it, either: there are many tricks with ordinary tags and attributes.

The fix is the order: escape first, then add the line breaks, then print raw. The text can no
longer contain working tags, and only our own `<br>`s are real. So that nobody (including another
developer) forgets the escaping, it lives in the model as an accessor, the same way as the
snippet:

```php
public function displayBody(): Attribute {
    return Attribute::get(function () {
        return nl2br(htmlspecialchars($this->body));
    });
}
```

```html
<p>{!! $post->displayBody !!}</p>
```

### 3. 🏷️ Named routes

Links were written by hand: `/buttons`, `/post/{{ $post->id }}`. Now imagine the client wants
the address changed, say from `/post` to something Estonian, or shorter. Every link to it in every
view has to be found and changed. Search and replace helps, but links can be written in many
ways, and in a big system one is always missed. In our menu the same link was already in two
places (the mobile menu and the desktop menu).

A little more work now saves a lot later. Every route gets a name:

```php
Route::get('/', [PublicController::class, 'index'])->name('home');
Route::get('/buttons', [PublicController::class, 'buttons'])->name('buttons');
Route::get('/post/{post}', [PublicController::class, 'post'])->name('post');
```

and links are generated from the name with `route()` (the Laravel extension for VS Code even
suggests the names):

```html
<li><a href="{{ route('buttons') }}">Buttons</a></li>
```

Changing the path in `routes/web.php` now changes every link at once. This is called reverse
routing: instead of the router reading a URL, we ask the router for the URL of a name.

For a route with a parameter, the second argument fills it in. It can even be the whole post:
Laravel takes the id from the model itself.

```html
<a href="{{ route('post', $post) }}" class="btn btn-primary">@lang('Read more')</a>
```

### 4. 🌍 Translation strings

We already saw `__()` in the pagination view. The texts in our own views (menu items, buttons,
headings, not the posts themselves) should go through it too, for the day the site needs a
second language:

```html
<h1>{{ __('Home Page') }}</h1>
```

Nothing changes on the page: when there is no translation, the key itself is printed.
`@lang('Read more')` is the Blade directive version of the same thing, it works identically and
does not need the `{{ }}` around it.

![Translations](https://api.memegen.link/images/mb/Member_____()_from_the_pagination_view~q/Ohh_I_member.png)

### 5. 🗂️ The admin list of posts

Writing posts straight into the database is no way to run a blog. The admin side starts with
`PostController`, the resource controller `make:model --all` generated with its seven empty
methods. `index` lists the posts:

```php
public function index()
{
    $posts = Post::paginate(16);
    return view('posts.index', compact('posts'));
}
```

```php
Route::get('/admin/posts', [PostController::class, 'index'])->name('posts.index');
```

The public home page keeps the simple paginator, but in the admin view we want proper page
numbers. Views for posts go into their own folder, `resources/views/posts`, hence `posts.index`.

The menu's example "Parent" item became "Admin", with a "Posts" link, in both menus:

```html
<summary>Admin</summary>
<ul class="p-2 bg-base-100 w-40 z-1">
    <li><a href="{{ route('posts.index') }}">Posts</a></li>
```

The list itself is a daisyUI table with zebra stripes. The rows show the id, title and the two
timestamps, and the last column has a `join` of buttons for the actions that come next:

```html
<table class="table table-zebra">
...
<tr class="hover:bg-base-300">
    <td>{{ $post->id }}</td>
    <td>{{ $post->title }}</td>
    <td>{{ $post->created_at }}</td>
    <td>{{ $post->updated_at }}</td>
    <td>
        <div class="join">
            <a class="btn btn-info">View</a>
            <a class="btn btn-warning">Edit</a>
            <a class="btn btn-error">Delete</a>
        </div>
    </td>
</tr>
```

Sixteen rows are already long. So the table repeats its headings in a `tfoot` (by the bottom you
may have forgotten which column was which), and the page links are both above and below it, so
the next page is reachable without scrolling back up. A "New Post" button sits on top, not yet
linked anywhere.

## ✅ Takeaways

1. **HTML ignores newlines**: `nl2br()` turns them into `<br>`.
2. **`{{ }}` escapes, `{!! !!}` does not.** Raw output of user text is an XSS hole.
3. **Escape first, then `nl2br`**, and keep it in a model accessor so it is never forgotten.
4. **Name every route** and link with `route()`; the path can then change in one place.
5. **`__()` or `@lang()`** for interface texts, ready for more languages.
6. **Admin views in their own folder**, a resource controller behind them.
