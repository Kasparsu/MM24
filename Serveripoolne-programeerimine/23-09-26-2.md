## 🗂️ Topics Covered

> 🗂️ Models exist, so now something has to use them. A resource gets its own controller,
> its own folder of views, and the beginnings of a create form.

### 1. 🎮 A controller per resource

```php
namespace App\Controllers;

use App\Models\Article;

class ArticlesController
{
    public function index() {
        $articles = Article::all();
        $title = 'Articles';
        view('articles/index', compact('title', 'articles'));
    }

    public function create() {
        $title = 'New Article';
        view('articles/create', compact('title'));
    }

    public function store() {
        dump($_POST);
    }
}
```

`PublicController` holds the pages that are just pages. Anything that is a **resource**:
something you list, add to, change: gets its own controller. The method names are the
conventional ones:

| Method | Job |
|---|---|
| `index` | show the list |
| `create` | show the form for a new one |
| `store` | receive that form |

`store()` currently only dumps `$_POST`. That is deliberate: prove the data arrives before
writing anything to the database.

### 2. 📁 Views in folders

`views/articles/index.php` and `views/articles/create.php`. Once a project has more than a
handful of pages, a flat `views/` folder stops being navigable: grouping by resource
means everything about articles sits together.

### 3. 🧰 `compact()`

```php
view('articles/index', compact('title', 'articles'));
```

`compact('title', 'articles')` builds `['title' => $title, 'articles' => $articles]` from
variables that already exist. It saves repeating each name twice, and it is why the
variable in the controller and the variable in the view always have the same name.

### 4. 🎨 Bootstrap pieces for the pages

The list and the form were built from ready-made components rather than hand-written CSS:

- **Tables** for the article list: <https://getbootstrap.com/docs/5.3/content/tables/>
- **Form controls** for the create form: <https://getbootstrap.com/docs/5.3/forms/form-control/#example>
- **Button groups** for the row actions: <https://getbootstrap.com/docs/5.3/components/button-group/>

Same argument as with the blog template earlier: on the back end the markup usually
arrives from someone else, and reading it is the skill that matters.

## ✅ Takeaways

1. **One controller per resource**, with `index` / `create` / `store` doing the expected jobs.
2. **Dump before you store.** Confirm the data arrives, then write it.
3. **Group views by resource** once there is more than a handful.
4. **`compact()`** hands variables to the view without repeating every name.
