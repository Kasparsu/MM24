### 1. 📅 Realistic created and updated dates

All 1000 seeded posts had been created in the same second, so every card said "1 hour ago" and
the dates told you nothing. The factory can fill `created_at` and `updated_at` itself. Faker's
`dateTimeBetween()` with no arguments returns a random moment between 30 years ago and now,
which we wrap in a `Carbon` object so we can do date maths on it.

A post can not be updated before it was created, so the update time is picked between the
creation time and three days later (things usually get fixed right away, not ten years on).
And most posts are never edited at all: `rand(0, 9)` gives a number from 0 to 9, and since 0 is
falsy the `if` is true 90% of the time, which keeps `updated` equal to `created`. Only a 10%
chance remains for a real edit.

```php
$created = Carbon::create(fake()->dateTimeBetween());
$updated = fake()->dateTimeBetween($created, Carbon::create($created)->addDays(3));
if(rand(0,9)){
    $updated = $created;
}

return [
    'title' => fake()->sentence(),
    'body' => fake()->paragraphs(6, true),
    'created_at' => $created,
    'updated_at' => $updated,
];
```

Note the `Carbon::create($created)` inside: `addDays()` changes the object it is called on, so
a copy is made to keep `$created` itself untouched.

### 2. 🔢 IDs in the same order as the dates

One more giveaway: in a real database the oldest post has id 1, the next id 2, and so on, but
our random dates were saved in random order. The seeder now sorts the made (not yet saved)
posts by date before saving, so the auto increment ids follow the creation times:

```php
$posts = Post::factory(1000)->make()->sortBy('created_at');
```

`make()` returns a collection, and `sortBy()` is a collection method, so no extra query is
needed.

### 3. 🏞️ Placeholder pictures from Lorem Picsum

Next, pictures on the post cards. Last year we tried several placeholder image services; some
have only a handful of pictures. [Lorem Picsum](https://picsum.photos/) has plenty, and a plain
`picsum.photos/1280/960` gives a new random picture on every request. We want different
pictures per post, but the same picture after a refresh, and that is what the seed form is
for: `picsum.photos/seed/<anything>/<width>/<height>` always returns the same picture for the
same seed. A `uuid` makes a good unique seed.

The quick version: a nullable `image_path` column straight on the `posts` table, filled by the
factory 90% of the time (a post without a picture is allowed):

```php
$imageUrl = null;
if(rand(0,9)){
    $imageUrl = 'https://picsum.photos/seed/'. fake()->uuid() .'/1280/960';
}
```

In PHP strings are joined with a dot, so the URL is built from three pieces. The commented out
`<figure>` in the post card came back, shown only when there is a picture:

```html
@if($post->image_path)
 <figure>
    <img src="{{ $post->image_path }}" />
</figure>
@endif
```

![Picsum seed](https://api.memegen.link/images/rollsafe/Need_a_fixed_random_picture~q/Put_a_uuid_in_the_picsum_seed.png)

### 4. 🤔 Why one column is a trap

This works, and the commit is called "bad single image example" on purpose. A client says "one
picture per post" today and asks for a gallery a few weeks later. With a column on `posts`, that
means rebuilding the table, the factory and every view that uses it. Some things really are one
of a kind (a profile picture, an avatar), but most of the time it pays to plan for change from
the start, so later changes stay small.

The better way is a separate model. The command one of the students dropped in the chat makes
everything at once:

```bash
php artisan make:model Image -a
```

`-a` (all) creates the model plus its migration, factory, seeder, policy, resource controller
and store and update form requests, just like we did for posts.

### 5. 🔗 Image belongs to Post: a one to one relationship

The `images` table gets the path and a foreign key to the post, the same `foreignIdFor` we used
for the post's user. Deleting a post deletes its image too. The `image_path` column was removed
from `posts` again.

```php
Schema::create('images', function (Blueprint $table) {
    $table->id();
    $table->string('path');
    $table->foreignIdFor(Post::class)->unique()->constrained()->cascadeOnDelete();
    $table->timestamps();
});
```

`path` is not nullable here: a post without a picture simply has no row in `images`. The
`unique()` is what makes it one to one. As long as the client wants only one picture, the
database itself refuses a second image for the same post. Allowing several later means dropping
that one word, not redesigning the tables.

The two models describe both directions of the relationship:

```php
// Post.php
public function image() {
    return $this->hasOne(Image::class);
}
```

```php
// Image.php
public function post() {
    return $this->belongsTo(Post::class);
}
```

![Unique](https://api.memegen.link/images/mw/unique()_on_post__id/One_image_per_post,_guaranteed_by_the_database.png)

### 6. 🌱 Seeding images and showing them

The picsum URL moved into `ImageFactory` (`'path' => 'https://picsum.photos/seed/'. fake()->uuid() .'/1280/960'`).
The new `ImageSeeder` needs only the post ids, so it selects just that column, and again gives
90% of the posts a picture:

```php
$posts = Post::select('id')->get();
foreach($posts as $post) {
    if(rand(0, 9)) {
        Image::factory()->create(['post_id' => $post->id]);
    }
}
```

It has to run after the posts exist, so it goes last in `DatabaseSeeder`:

```php
$this->call(UserSeeder::class);
$this->call(PostSeeder::class);
$this->call(ImageSeeder::class);
```

The post card now asks the relationship instead of the column:

```html
@if($post->image)
 <figure>
    <img src="{{ $post->image->path }}" />
</figure>
@endif
```

After reseeding, the cards look the same as before, but the data is ready for more.
Next lesson: what has to change to allow several pictures per post (not much in the database).

## ✅ Takeaways

1. **Fake dates in the factory**: `fake()->dateTimeBetween()` for `created_at`, and an `updated_at` no earlier than it.
2. **`rand(0, 9)` in an `if`** is true 90% of the time: an easy way to make something rare.
3. **`make()->sortBy('created_at')`** before saving keeps ids in the same order as the dates.
4. **`picsum.photos/seed/<uuid>/w/h`** gives a random picture that stays the same on refresh.
5. **Plan for change**: a separate `Image` model instead of an `image_path` column on `posts`.
6. **`foreignIdFor(Post::class)->unique()`** plus `hasOne` / `belongsTo` makes a one to one relationship enforced by the database.
