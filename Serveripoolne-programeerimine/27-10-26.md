## 🗂️ Topics Covered

### 1. 📋 Where things stand, and an extra task

The lesson started a few minutes late because the teacher's microphone was muted. Then the plan:
whoever has the tasks done can relax a bit; whoever is behind should use the time to finish
them, because they will be graded together at the end of the period and the teacher would rather
not spend a whole week on resubmissions.

For those who are done there is an extra task, building directly on yesterday:

- a **tag page**: clicking a tag badge on a post card opens a page with only the posts that have
  that tag, the same way the author's name now opens the user page;
- it **reuses the existing `welcome` view**, just like the user page did, so no new view is needed;
- tags get **slugs** too, the same way users got them yesterday: the `Sluggable` attribute naming
  the field the slug is made from, `getRouteKeyName()`, and a `slug` column in the migration.

To show what that took for users, the "Add slugs to users" commit was shared in the chat. It is
not urgent and it is a small task.

A student asked why the slug did not work in their project although the code was the same. The
usual reason: the column was added to the migration in the code, but the database never got it,
because the migrations were not run again. With Laravel you always have to keep two things in
sync, the code and the state of the database (and installed packages: after a pull, maybe a
`composer install` is missing).

### 2. 🧭 Where the course goes next

The material for this subject is running out, and that is on purpose. What we did, plain PHP and
then Laravel, is the foundation, and it is not wasted. But today web applications are often
built a bit differently, and the second subject (where the rest of the hours are) will look at
those more modern approaches. Time will also go into preparing for the exam.

### 3. 🤖 Learning with an AI assistant

Many students use AI tools for the tasks. The teacher's point: that is not bad by itself, but
combine it with your own knowledge and you get much better results.

- **The assistant assumes you are an experienced developer.** In a Laravel project the AI sees a
  real project with best practice rules and tests (the teacher's own setup even has Laravel Boost
  files for Claude), so it answers at the level of someone who already knows the field. Tell it
  who you are: "I'm a multimedia student, this is my second year of programming, explain it at
  that level." The teacher's comparison: asking for a carbonara recipe gives you one written for
  someone who can cook, but asking "explain it like to someone who has never cooked, and tell me
  the classic mistakes" gives something you can actually follow.
- **Ask it to put the prerequisites first**, so you do not hit "but before this step you should
  have..." halfway through.
- **Write that context down once** instead of retyping it every time.
- **Feed it the course material.** The Tahvel lesson descriptions and the detailed lesson
  summaries on GitHub describe what was covered. Given those, an AI can make you a map of the
  terms and topics you are expected to know, which is good exam preparation.
- It does not replace knowing the terms: the better you can describe what you want, the better
  the result.

## ✅ Takeaways

1. **Behind on tasks? Finish those first**; they are graded together at the end of the period.
2. **Extra task**: a tag page that reuses the `welcome` view, plus slugs for tags, modelled on the user page and user slugs.
3. **Code and database must match**: a column in a migration does nothing until the migrations are run.
4. **Next subject**: more modern ways of building web apps on top of this foundation, plus exam preparation.
5. **Tell the AI your level** and ask for prerequisites first; write that context down once.
6. **Give the AI the course material** (Tahvel descriptions, GitHub summaries) to get a map of what you should know.
