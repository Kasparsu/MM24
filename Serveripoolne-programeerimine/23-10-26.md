### 1. 🔐 First, a login that would not work

The lesson started with a login failing with "These credentials do not match our records".
We followed how the default user gets its password. `UserSeeder` creates it from the `.env`
file, or falls back to a hash of the word `password`:

```php
'password' => env('DEFAULT_USER_PASSWORD_HASH', Hash::make('password')),
```

So the password stored in the database is always a hash: either the one written into
`DEFAULT_USER_PASSWORD_HASH`, or one made from `password` (the `UserFactory` does the same for
the ten random users). The `User` model also has a `hashed` cast on the password, which hashes
plain text on save. When login fails after a reseed, check what is actually in the `.env`
file and what the seeder put into the `users` table (Tinker is handy for that) before
suspecting the login code.

### 2. ☑️ Checkboxes instead of a multiple select

Last time the tag `<select multiple>` broke the daisyUI styling. Instead of fighting it, the
select was replaced with one checkbox per tag. The markup was pasted into the meeting chat so
everyone could copy it:

```html
<fieldset class="fieldset">
    <legend class="fieldset-legend">Tags</legend>
    <div class="flex flex-wrap gap-2">
        @foreach ($tags as $tag)
            <input type="checkbox" name="tags[]" value="{{ $tag->id }}" aria-label="{{ $tag->name }}"
                class="btn btn-sm" @checked(in_array($tag->id, old('tags', []))) />
        @endforeach
    </div>
    <span class="label">Optional</span>
</fieldset>
```

What each part does:

- **`name="tags[]"`**: the same trick as `images[]` for multiple files. Every ticked box sends
  a value under the same name, and the square brackets make PHP collect them into an array.
- **`value="{{ $tag->id }}"`**: the form sends tag ids, not names. The pivot table stores ids,
  so that is exactly what the controller needs.
- **`class="btn btn-sm"` with `aria-label`**: daisyUI draws a checkbox with the `btn` class as a
  toggle button and shows the `aria-label` text on it. A ticked tag looks like a pressed button.
- **`flex flex-wrap gap-2`**: the buttons sit in a row and wrap to the next line when there are
  many tags.
- **`@checked(...)` with `old('tags', [])`**: if validation fails (say, the title is missing),
  the form comes back with the tags still ticked. `old('tags', [])` gives the previously sent
  ids, or an empty array the first time, and `@checked` prints `checked` when the id is in it.

### 3. 💾 Saving the chosen tags

The form now sends an array of tag ids, and `PostController@store` hands it to the
relationship. One line after the post and its images are saved:

```php
$post->tags()->attach($request->input('tags'));
```

`attach()` is the same method the `TagSeeder` used last lesson. Besides models and
collections, it also takes a plain array of ids and writes one `post_tag` row for each. The
post has to be saved first, since the pivot rows need its id.

The tags are not validated yet. A rule checking that every sent id really exists in the `tags`
table would be a good next step, just like `images.*` checks every uploaded file.

### 4. 🩹 A post without images crashed

While testing, creating a post without picking any images failed with an error saying the
`foreach()` argument must be of type array or object. With no files chosen,
`$request->file('images')` returns `null`, and a `foreach` over `null` is an error. The null
coalescing operator turns it into an empty array, so the loop simply runs zero times:

```php
foreach($request->file('images') ?? [] as $file) {
```

`??` means "use the left side, unless it is null, then use the right side". Images and tags
are both optional now, and a post can be created with neither.

## ✅ Takeaways

1. **Seeded passwords are hashes**: the default user's comes from `DEFAULT_USER_PASSWORD_HASH` or `Hash::make('password')`; check `.env` and the `users` table when login fails.
2. **No multiple select in daisyUI? Use checkboxes**: one `<input type="checkbox" class="btn">` per tag, labelled with `aria-label`.
3. **`name="tags[]"`** sends all ticked values as an array, with the tag **id** as the value.
4. **`@checked(in_array($tag->id, old('tags', [])))`** keeps the ticks when validation sends the form back.
5. **`$post->tags()->attach($ids)`** saves the chosen tags into `post_tag`, after the post itself is saved.
6. **`$request->file('images') ?? []`**: never `foreach` over something that can be `null`.
7. **Next**: validate the tag ids, and build the Tags CRUD from the Teams task.
