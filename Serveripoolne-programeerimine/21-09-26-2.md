## 🗂️ Topics Covered

> from a POST, and the project gets a database file to talk to next.

### 1. 🚦 The router learns about methods

A route used to be just a path. Now it is a path **and** a method:

```php
public static function addRoute($method, $path, $action) {
    self::$routes[] = ['method' => $method, 'path' => $path, 'action' => $action];
}

public static function get($path, $action)  { self::addRoute('GET',  $path, $action); }
public static function post($path, $action) { self::addRoute('POST', $path, $action); }
```

and matching compares both:

```php
public function match() {
    foreach (self::$routes as $route) {
        if ($route['path'] === $this->path && $route['method'] === $this->method) {
            return $route;
        }
    }
    return false;
}
```

That is what makes this possible in `routes.php`:

```php
Router::get('/forms',  [PublicController::class, 'forms']);   // show the form
Router::post('/forms', [PublicController::class, 'answer']);  // receive it
```

**Same address, two different jobs.** Visiting `/forms` shows the form; submitting it
posts to the same `/forms` and runs different code. This is the normal shape of web
applications, and it only works once the method is part of the match.

![Method matters](https://api.memegen.link/images/bus/Same_path/Different_method.png)

### 2. 🧯 `get()` and `post()` are conveniences

`addRoute` is the real function; `get()` and `post()` just call it with the method filled
in. That is a small lesson in its own right: when a function takes an argument that is
almost always one of two values, wrapping it makes the calling code read better without
adding any new behaviour.

> ⚠️ Worth knowing if you pull this change: `addRoute` now takes **three** arguments. Old
> two-argument calls (`Router::addRoute('/', ...)`) stop matching and every page 404s.
> Rewrite them to `Router::get(...)`.

### 3. 🗄️ A database file appears

`db.sqlite` was added to the project — an SQLite database is a single file, no server to
install and no credentials to configure. Nothing reads from it yet; this is the groundwork
for the connection class in the next session.

## ✅ Takeaways

1. **A route is a path plus a method.** Without that, one address can only do one thing.
2. **`GET /forms` shows, `POST /forms` receives.** Same URL, different code.
3. **`get()`/`post()` are wrappers over `addRoute`.** Same behaviour, better reading.
4. **SQLite is one file.** No server, no credentials — ideal for learning.
