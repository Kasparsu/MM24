## 🗂️ Topics Covered

> 🧱 The last piece of the pattern. Data stops being fetched inline and becomes a class
> that knows its own table.

### 1. 🏛️ MVC — what goes where

| Layer | Answers | In this project |
|---|---|---|
| **Model** | where does the data live, what shape is it | `src/Models/` |
| **View** | what does the user see | `views/` |
| **Controller** | what happens on this request | `src/Controllers/` |

The rule of thumb: a view should not know SQL, and a model should not know HTML. The
controller is the only one allowed to talk to both.

Reference: <https://en.wikipedia.org/wiki/Model%E2%80%93view%E2%80%93controller>

![MVC](https://api.memegen.link/images/3hd/Model:_the_data/View:_the_markup/Controller:_the_glue.png)

### 2. 🧬 An abstract base model

```php
abstract class Model {
    public $id;
    protected static string $table;

    public static function all() {
        $db = new DB();
        return $db->all(static::$table, static::class);
    }
}
```

Three things worth slowing down for:

- **`abstract`** means you cannot do `new Model()`. It exists only to be extended — there
  is no such thing as "a model" in general, only articles, users and so on.
- **`static::$table`** is *late static binding*. Written as `self::$table` it would always
  mean `Model`'s own property; `static::` means "whichever class was actually called".
  So `Article::all()` reads `'articles'` and `User::all()` reads `'users'`, from the same
  inherited method.
- **`static::class`** is that class's name as a string — exactly what `FETCH_CLASS` needs.

### 3. 📄 A concrete model

```php
class Article extends Model {
    protected static string $table = 'articles';

    public $id;
    public $title;
    public $body;
    public $date;
    public $author;
}
```

Almost no code: a table name and the columns. All the behaviour is inherited. Adding a
`User` model later is the same five lines with different words — which is the payoff for
having written the abstract class first.

### 4. 🖨️ Articles from the database

The index page stopped containing a hand-written `$posts` array and started with:

```php
$articles = Article::all();
```

Same view, same partials, same loop — the only difference is where the rows came from.
That is the moment the project becomes an actual application rather than a styled
template.

## ✅ Takeaways

1. **Views don't do SQL, models don't do HTML.** The controller connects them.
2. **`abstract` = cannot be instantiated.** A base class is a shape, not a thing.
3. **`static::` vs `self::`** — late static binding is what lets one inherited `all()`
   serve every model.
4. **A model is mostly declaration.** Table name plus columns; behaviour comes from the parent.
