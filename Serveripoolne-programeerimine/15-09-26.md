## 🗂️ Topics Covered

> 🚏 The step from "a folder of .php files" to "one entry point that decides what to show".
> This is the shape every PHP framework uses.

### 1. 📂 Restructuring the Project

Files moved into a deliberate layout:

```
public/          ← the only directory the web server exposes
  index.php      ← the single entry point
  assets/        ← css, js, images
  blog.css
views/           ← templates, NOT directly reachable
  index.php
  us.php
  partials/
server.sh
```

**Why `public/` exists:** everything the browser may request goes in there and **nothing
else**. Templates, and later configuration and database credentials, sit *outside* it, so
there is no URL that can reach them even by accident.

**Serving it:**
```bash
php -S localhost:8000 -t public public/index.php
```

| Flag | Meaning |
|---|---|
| `-t public` | Document root is `public/` |
| `public/index.php` | **Router script**: every request goes here first |

### 2. 🎯 The Front Controller

`public/index.php` now receives *every* request:

```php
<?php
if (preg_match('/\.(?:png|jpg|jpeg|gif|css|js)$/', $_SERVER["REQUEST_URI"])) {
    return false;    // serve the requested resource as-is.
}

switch ($_SERVER['REQUEST_URI']) {
    case '/':
        include __DIR__ . '/../views/index.php';
        break;
    case '/us':
        include __DIR__ . '/../views/us.php';
        break;
    default:
        echo '404';
}
```

**Reading it:**

- **`$_SERVER['REQUEST_URI']`**: the path the browser asked for. This is the first
  *superglobal*: an array PHP fills in with information about the request.
- **The `preg_match` guard**, if the request is for a real file (`.css`, `.js`, an image),
  `return false` tells the built-in server "just serve that file normally". Without it, every
  stylesheet request would also run the router.
- **The `switch`**: match the path, include the right view.
- **`default: echo '404'`**: nothing matched.
- **`__DIR__`**: the directory of *this* file, so includes work regardless of where the
  script was started from.

**URLs get nicer as a side effect:** `/us` instead of `/us.php`. The path is now a *name you
choose*, not a filename on disk, so `nav.php` updates to `href="/us"`.

### 3. 🛠️ A `dump()` Helper

```php
function dump(...$vars) {
    echo '<pre>';
    var_dump(...$vars);
    echo '</pre>';
}
```

`var_dump()` output in a browser is an unreadable wall: HTML collapses the whitespace.
Wrapping it in `<pre>` keeps the formatting.

**`...$vars`** is the **spread/variadic** operator: the function accepts any number of
arguments, collects them into an array, and `var_dump(...$vars)` spreads them back out. So
`dump($a, $b, $c)` works exactly like `var_dump($a, $b, $c)`.

### 4. 📊 Data in the Router, Markup in the View

The second commit moves the page's **data** into the route:

```php
case '/':
    $title = 'World';
    $posts = [
        ['title' => 'Some world title 1', 'content' => '…',
         'date' => 'January 1, 2021', 'author' => 'Pets'],
        // …
    ];
    include __DIR__ . '/../views/index.php';
    break;
```

Variables defined **before** an `include` are visible **inside** the included file. So the
view stops containing hard-coded post markup and starts looping over `$posts` instead.

**This is the separation that matters:**

| Layer | Responsibility |
|---|---|
| Router (`public/index.php`) | Decide what page this is, gather the data |
| View (`views/…`) | Turn data into HTML |

The two pages now differ only in their data: the same partials render both.

## ✅ Takeaways

1. **Only `public/` is web-reachable.** Templates and secrets live outside it.
2. **One entry point**: `php -S localhost:8000 -t public public/index.php`.
3. **`$_SERVER['REQUEST_URI']`** is the requested path; `return false` lets real files through.
4. **`__DIR__`** makes includes independent of the working directory.
5. **`...$vars`** collects and spreads arguments.
6. **Variables set before `include` are visible inside it**: that's how data reaches a view.
