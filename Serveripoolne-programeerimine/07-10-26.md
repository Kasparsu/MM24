### 1. 🌬️ Living with long Tailwind classes

Anyone who did the homework found out: anything pretty in pure Tailwind takes a lot of classes.
That is also its strength, since everything can be changed, and the class names get familiar
fast once you force yourself to use them. Many are logical (`rounded`, sizes, shadows,
colours). Helpers:

- **Components.** Instead of repeating a long button everywhere, frameworks (and Laravel too)
  let you put it in its own file and just use it. Coming later.
- **Editor extensions**: Tailwind IntelliSense suggests class names, and class-folding
  extensions hide the long class lists until you click on them.

### 2. 🧩 Component libraries

There are two kinds:

- **Copy-paste HTML**: libraries of ready-made pieces written in plain Tailwind classes. Nothing
  to install; copy the HTML. The button group in the commit came from such a library:

  ```html
  <button
      class="rounded-s-sm border border-gray-200 px-3 py-2 font-medium text-gray-700 transition-colors hover:bg-gray-50 hover:text-gray-900 focus:z-10 focus:ring-2 focus:ring-blue-500 focus:ring-offset-2 focus:ring-offset-white focus:outline-none disabled:pointer-events-auto disabled:opacity-50">
      View
  </button>
  ```

- **Plugins** that add Bootstrap-like component classes, built from Tailwind behind the scenes.

Why not just go back to Bootstrap then? Because Tailwind's spacing and colour scale keeps the
design within limits (no 7 px here, 8 px there and 17 px somewhere else), and with a plugin you
get short component classes **and** can still tune any detail with Tailwind classes.

![Utility classes](https://api.memegen.link/images/buzz/Utility_classes/Utility_classes_everywhere.png)

### 3. 🌼 daisyUI

The plugin of choice is daisyUI (<https://daisyui.com/docs/install/>). Its classes are so close
to Bootstrap's that a lot of Bootstrap markup works almost as is, and it comes with many themes
(light, dark, cupcake, emerald, abyss, caramellatte and so on), easy to switch or tune. The
teacher's own timetable app is built with it too.

Installing it with Bun:

```
bun add -D daisyui
```

and one line at the end of `resources/css/app.css`:

```css
@plugin "daisyui";
```

Then a full button is just:

```html
<button class="btn btn-primary">Click me!</button>
```

### 4. ⌨️ Two editor shortcuts

- **Ctrl+P** opens any file by name. Laravel has many folders, and many files with similar
  names; typing `User` and picking `app/Models/User.php` beats clicking through the tree. The
  less you need the mouse, the faster you work.
- **Ctrl+click** on a class or method name jumps to it, opening the file if needed.

### 5. 🧰 `php artisan`

`php artisan list` shows all of Laravel's commands. One we already used: `key:generate`. A new
`.env` from `.env.example` has no `APP_KEY`, and without it the app errors out. The key encrypts
the session and cookie data, so it cannot be read without the key: Laravel generally tries to
protect you from your own mistakes.

A large group are the `make:` commands that generate classes. They usually write more boilerplate
than we would by hand, and correctly:

```
php artisan make:controller PublicController
```

Like `PublicController` in learnphp, it is for the public pages:

```php
class PublicController extends Controller
{
    public function index() {
        return view('welcome');
    }

    public function buttons() {
        return view('buttons');
    }
}
```

and the routes point to it the same way ours did:

```php
use App\Http\Controllers\PublicController;
use Illuminate\Support\Facades\Route;

Route::get('/', [PublicController::class, 'index']);
Route::get('/buttons', [PublicController::class, 'buttons']);
```

The button examples moved to their own `/buttons` page, so the home page is free.

### 6. 🧱 A Blade layout

In learnphp every view included a header and a footer partial. Blade does it the other way
round: one **layout** with the whole page, and a hole where each page's content goes.
`resources/views/partials/layout.blade.php`:

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
    @vite('resources/css/app.css')
</head>

<body>
    @include('partials.nav')
    @yield('content')
</body>
</html>
```

`@yield('content')` names the hole. A page then **extends** the layout and fills the section:

```html
@extends('partials.layout')
@section('content')
<h1>Home page</h1>
@endsection
```

View names use a **dot** instead of a slash (`partials.layout` is `partials/layout.blade.php`).
A slash works too, but Laravel prefers the dot, and editor plugins only recognise the dot version
for jumping to the file. The trick to check it works: remove the `@extends` and the page shows
only the bare content.

![Layout](https://api.memegen.link/images/exit/Copy_the_head_into_every_view/@extends_partials.layout/Blade_views.png)

### 7. 🧭 A daisyUI navbar

The navbar is copied from daisyUI's "responsive dropdown menu on small screen, center menu on
large screen" example
(<https://daisyui.com/components/navbar/#responsive-dropdown-menu-on-small-screen-center-menu-on-large-screen>)
into `partials/nav.blade.php`. On a narrow screen it turns into a hamburger dropdown.

It does that without JavaScript, by containing **two menus**: one shown on mobile
(`lg:hidden`), one on large screens (`hidden lg:flex`). So a link has to be added in both places:

```html
<li><a href="/buttons">Buttons</a></li>
```

### 8. ⚙️ `config('app.name')`

The logo text in the navbar should not say "daisyUI", and maybe not even "blog", since someone
else might use the same system for their own blog. So it reads the app name from the config:

```html
<a class="btn btn-ghost text-xl" href="/">{{ config('app.name') }}</a>
```

`config('app.name')` is a Laravel helper: the file name (`app`) and the key (`name`). In
`config/app.php` that value comes from `env('APP_NAME', 'Laravel')`, which looks in this order:

1. a real system environment variable with that name,
2. the project's `.env` file,
3. the default given as the second argument.

So changing `APP_NAME` in `.env` changes the navbar. (In class the new name did not appear
right away and took a little poking around.)

## ✅ Takeaways

1. **daisyUI gives Tailwind Bootstrap-like components** (`btn btn-primary`), and Tailwind classes still tune them.
2. **`php artisan make:...` generates classes**; `key:generate` fills a missing `APP_KEY`.
3. **One layout, many pages**: `@yield` in the layout, `@extends` plus `@section` in the page.
4. **View names use dots**: `partials.layout`.
5. **`config('file.key')`** reads settings, which mostly come from `.env` via `env()`.
