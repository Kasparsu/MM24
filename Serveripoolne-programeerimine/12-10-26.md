### 1. 🔘 Finishing the pagination view

The rest of the long Tailwind classes became daisyUI buttons inside the `join` group. The `...`
separator is a disabled button, every other page number a link:

```html
@if (is_string($element))
    <button class="join-item btn btn-disabled">...</button>
@endif
```

The current page needs to stand out. With `btn-active` it was hard to tell on a dark theme which
page is the current one (on a light theme it is easier), so it got the theme's primary colour:

```html
@if ($page == $paginator->currentPage())
    <button class="join-item btn btn-primary"
        aria-current="page">{{ $page }}</button>
@else
    <a href="{{ $url }}" class="join-item btn"
        aria-label="{{ __('Go to page :page', ['page' => $page]) }}">
        {{ $page }}
    </a>
@endif
```

Any other button colour works too (secondary, accent, info and so on), pick what suits your
theme. The "next" button got the arrow pointing the other way, and the `nav` got `my-2` so it
does not stick to the cards.

### 2. 📁 Our own pagination view as the default

`resources/views/vendor/pagination` was full of Bootstrap and Semantic UI views we will never
use. They were deleted, and the two Tailwind views were moved and renamed:
`partials/pagination.blade.php` and `partials/simple-pagination.blade.php`.

Now `links()` showed Laravel's original again: it only looks in `vendor/pagination`. One fix is
to give the view name every time (`$posts->links('partials.pagination')`), but that is easy to
forget. Better is to set it once, as the documentation shows
(<https://laravel.com/framework/docs/pagination#customizing-the-pagination-view>), in
`AppServiceProvider`:

```php
use Illuminate\Pagination\Paginator;
...
public function boot(): void
{
    Paginator::defaultView('partials.pagination');
    Paginator::defaultSimpleView('partials.simple-pagination');
}
```

Watch the import: Laravel is big and has several classes called `Paginator`. The editor
offers them all, and only `Illuminate\Pagination\Paginator` is the right one.

![Default view](https://api.memegen.link/images/sohappy/If_links()_used_my_daisyUI_view_everywhere/I_would_be_so_happy.png)

### 3. ⏭️ `simplePaginate()`

The home page switched to the simple version:

```php
$posts = Post::simplePaginate(16);
```

It only gives "previous" and "next". It does not know how many pages there are: the page number
is still in the address bar, but there are no numbers to click. Why would anyone want that? For
something simple it is enough, and it saves a query: to show page numbers, the full paginator
has to ask the database how many posts there are in total, on every page load.

The simple view is still the plain Tailwind one. Restyling it with daisyUI, the same way as the
big one (any button style you like, or the mobile part of the big view as a model), was left for
the students to do themselves.

### 4. ✂️ A snippet instead of the whole post

The cards show the whole body, and a real post can be much longer than our six fake paragraphs.
The card needs a short piece of it (an excerpt, a snippet). There is no point storing it
separately, it can be computed from the body. The model gets an **accessor**:

```php
public function snippet(): Attribute {
    return Attribute::get(function () {
        return explode("\n\n", $this->body)[0];
    });
}
```

Asking for `$post->snippet` (no brackets, like a column) runs the function: Laravel's model uses
the magic methods we met in learnphp to look for it. Our fake paragraphs are separated by an
empty line, two newline characters, so splitting at `"\n\n"` and taking the first piece gives the
first paragraph.

This only works because Faker's paragraphs are neat. Real text may have no paragraphs at all, or
a first paragraph that is very long. A real version would go step by step: the first paragraph if
it is short enough, else the first few sentences (split at `.`, `?`, `!`), else the first so many
words, and as a last resort a fixed number of characters with an ellipsis.

### 5. 🔗 A page for one post

"Read more" became a link, and the post page a new route. In learnphp we would have used a query
parameter (`/post?id=5`). Laravel's router supports **route parameters**: a `{name}` part of the
path that matches anything, so the link is a clean `/post/5`.

The parameter can be read from the request (`$request->route(...)`), or simply asked for as a
method parameter with the same name. Then `Post::find($id)` looks the post up, and `toArray()` on
it shows just the columns without the rest of the model's internals.

What about `/post/1001`, when there are only 1000 posts? `find` returns `null`, and the view
crashes. The answer should be a 404 page. Laravel has a set of exceptions for HTTP errors that it
catches itself and turns into a proper error page. A not found exception can be thrown by hand,
but this is so common that `findOrFail()` does it for us: the post or a 404.

It gets better. If the parameter is type hinted with the model, Laravel looks it up itself,
404 included. This is **route model binding**:

```php
Route::get('/post/{post}', [PublicController::class, 'post']);
```

```php
public function post(Post $post) {
    return view('post', compact('post'));
}
```

The name in the route (`{post}`) and the parameter name (`$post`) must match.

![Route model binding](https://api.memegen.link/images/keanu/What_if_the_route_parameter_is_called_post/and_Laravel_just_finds_the_post_for_you~q.png)

### 6. 📄 The post view

`post.blade.php` is the card from the home page without the picture and the button, showing the
whole body:

```html
<div class="card-body">
    <h2 class="card-title">{{ $post->title }}</h2>
    <p>{{ $post->body }}</p>
```

and the cards on the home page show the snippet and link to it:

```html
<p>{{ $post->snippet }}</p>
<div class="card-actions justify-end">
    <a href="/post/{{ $post->id }}" class="btn btn-primary">Read more</a>
</div>
```

## ✅ Takeaways

1. **The current page should stand out**: `btn-primary` instead of a barely visible active state.
2. **Set the pagination view once** with `Paginator::defaultView()` in `AppServiceProvider`.
3. **`simplePaginate()`** is previous and next only, and skips the count query.
4. **Accessors** (`Attribute::get`) compute values like a snippet from the columns.
5. **Route parameters** (`/post/{post}`) instead of query strings; `findOrFail()` gives a 404.
6. **Route model binding**: type hint `Post $post` and Laravel finds it, or answers 404.
