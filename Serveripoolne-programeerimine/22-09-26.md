## 🗂️ Topics Covered

> 🔌 The database file stops being decoration: one class opens the connection, and every
> query in the project goes through it.

### 1. 🔗 PDO: one interface, many databases

```php
$this->conn = new PDO("sqlite:" . __DIR__ . '/../db.sqlite');
```

PDO is PHP's database layer. The **DSN** (the string in front) is the only part that
knows which engine you are talking to:

```
sqlite:/path/to/db.sqlite
mysql:host=localhost;dbname=blog;charset=utf8mb4
```

Everything after that (`query`, `prepare`, `fetchAll`) is identical. Swapping SQLite for
MySQL later means changing one line, not rewriting the project.

Docs: <https://www.w3schools.com/php/php_mysql_connect.asp>

### 2. 🚨 Make errors loud

```php
$this->conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
```

By default PDO fails quietly: a broken query returns `false` and your page renders blank
while you stare at it. `ERRMODE_EXCEPTION` turns every failure into a thrown exception
with a message that names the problem. Set it immediately after connecting, every time.

The connection itself is wrapped:

```php
try {
    $this->conn = new PDO(...);
    ...
} catch (PDOException $e) {
    echo "Connection failed: " . $e->getMessage();
}
```

A missing file or a wrong password is not a bug in your code, it is a condition you should
report clearly.

### 3. 📦 One class owns the connection

```php
namespace App;

class DB {
    private $conn;

    public function __construct() { /* connect */ }

    public function all($table, $class) {
        $sql = "SELECT * FROM $table";
        $result = $this->conn->query($sql);
        $result->setFetchMode(PDO::FETCH_CLASS, $class);
        return $result->fetchAll();
    }
}
```

`$conn` is **private** on purpose. Nothing outside `DB` can reach the raw connection, so
every query has to go through a method here. When you later need logging, or prepared
statements everywhere, there is exactly one file to change.

Docs: <https://www.w3schools.com/php/php_mysql_select.asp>

### 4. 🎭 `FETCH_CLASS`: rows as objects

```php
$result->setFetchMode(PDO::FETCH_CLASS, $class);
```

Without it you get arrays: `$row['title']`. With it, PDO builds an object of the class you
name and assigns each column to a matching property: `$article->title`.

That single line is what turns a table row into something the rest of your code can treat
as a *thing* rather than a bag of strings, and it is the hinge the next session's models
hang on.

## ✅ Takeaways

1. **PDO speaks to every engine the same way.** Only the DSN changes.
2. **`ERRMODE_EXCEPTION` first, always.** Silent `false` is the worst way to learn a query
   is broken.
3. **Keep `$conn` private.** One class owns the connection, so there is one place to fix.
4. **`FETCH_CLASS` turns rows into objects**: the step that makes models possible.
