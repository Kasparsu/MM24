## 🗂️ Topics Covered

> ✍️ The admin can now write a post. The form is quick to build with daisyUI; the interesting
> part is everything Laravel checks on the way in: form request authorization, the CSRF token,
> validation rules with error messages, and mass assignment protection.

### 1. 📝 The create form

Very much like learnphp: a route that shows the form, and a controller method that only loads
the view. The method already exists in `PostController`:

```php
Route::get('/admin/posts/create', [PostController::class, 'create'])->name('posts.create');
```

```php
public function create()
{
    return view('posts.create');
}
```

The "New Post" button on the posts list finally links somewhere:
`href="{{ route('posts.create') }}"`.

The form fields come from daisyUI: an input in a fieldset with a legend
(<https://daisyui.com/components/input/#with-fieldset-and-fieldset-legend>) and a textarea
(<https://daisyui.com/components/textarea/#with-form-control-and-labels>). The form itself was
made to look like a card, two thirds wide and centred, with some padding. The inputs got `w-full`
(the fieldset is full width, the input inside is not), and the textarea `h-36` for some height:

```html
<form action="{{route('posts.store')}}" method="POST" class="card bg-base-300 shadow-sm w-2/3 mx-auto p-3">
    @csrf
    <fieldset class="fieldset">
        <legend class="fieldset-legend">Title</legend>
        <input name="title" type="text" class="input w-full @error('title') input-error @enderror" placeholder="Title" />
```

The example's small "optional" label was kept (commented out at first), because it is a good
place for error messages later. And the one thing a copied example never has: the **`name`**
attribute. Without it the field's value is not sent at all. In the textarea the field is `body`
(the developer's word), while the user sees "Content".

### 2. 📮 The store route and `authorize()`

The form posts to the same address with a different method:

```php
Route::post('/admin/posts', [PostController::class, 'store'])->name('posts.store');
```

`store()` does not get a plain `Request` but a `StorePostRequest`, one of the form request classes
`make:model --all` created. A first `dd($request->all())` to see what arrives gave **403, This
action is unauthorized**. Ctrl+click on the class shows why: its `authorize()` method returns
`false`.

Why would Laravel generate something that always says no? So that we have to think about it. If
it returned `true` by default, nobody would remember to add a real check later (only logged in
users may write posts). We do not have logins yet, so for now it is `true`, with a note:

```php
public function authorize(): bool
{
    // @todo make this secure later
    return true;
}
```

Such `@todo` comments do nothing by themselves, but editors and extensions (a todo extension was
installed for VS Code) can list them all, so they are easy to find later.

![authorize](https://api.memegen.link/images/grumpycat/authorize()_in_a_fresh_form_request/403._No..png)

### 3. 🎟️ `@csrf`

Laravel checks that a form submission comes from a form that our own site served. That protects
against **cross-site request forgery**: another site making your browser send a request to ours,
with your login (<https://laravel.com/framework/docs/csrf>). `@csrf` adds a hidden input with a
token, and the server checks the token comes back. Older Laravel versions refused every form
without it; newer ones can manage the check in modern browsers without the token, but it does
no harm and older browsers still need it, so every form gets `@csrf`.

### 4. 💾 Saving, and the NOT NULL error

Saving works like in learnphp: a new model, values from the request, `save()`. The two
assignments stayed in the commit as comments, after the shorter version below replaced them:

```php
// $post->title = $request->input('title');
// $post->body = $request->input('body');
$post->save();
```

The new post was in the database. But submitting with an empty title crashed: our migration
made `title` NOT NULL (only `body` is nullable), so the database refused the row.

![Empty title](https://api.memegen.link/images/facepalm/Submitting_the_form_with_an_empty_title/NOT_NULL_constraint_failed.png)

### 5. ✅ Validation rules

In learnphp we had no good way to say what is wrong. The form request has a `rules()` method for
exactly this, and Laravel has a long list of ready rules: required, sizes, min and max, starts
with, email, URL and many more
(<https://laravel.com/framework/docs/validation#available-validation-rules>):

```php
public function rules(): array
{
    return [
        'title' => 'required',
        'body' => 'nullable'
    ];
}
```

With an empty title Laravel now sends the user back to the form, which looks like nothing
happened (watch the refresh button flicker). It sends the errors along, though, and Blade's
`@error` shows them, with daisyUI's error colours:

```html
@error('title')
    <p class="label text-error">{{$message}}</p>
@enderror
```

The input itself turns red the same way, with `input-error` (and `textarea-error` for the
textarea) inside an `@error ... @enderror` in its class list. The same block went under the
body field too: no rule can fail there yet, but the day a length limit is added, it is ready.

### 6. 🧺 Mass assignment

Two fields are quick to copy one by one. A government form or a long survey has dozens, and
nobody wants to write a hundred such lines. A model can be filled from an array in one go:

```php
$post = new Post($request->validated());
```

Why `validated()` and not `all()`? Because the user controls what is sent. A hidden `id` input
was added to the form in the browser's dev tools, and `all()` happily included it. Filled into
the model, the post would have that id, so Laravel would **overwrite an existing post** instead
of creating a new one. Golden rule: **never trust user input**. `validated()` returns only the
fields that have validation rules (which is why `body` has its `nullable` rule).

Laravel does not know we were careful, so it still refused with a mass assignment error. The
model has to list the fields that may be filled this way:

```php
protected $fillable = ['title', 'body'];
```

For two fields it saves little, but on a big form, listing the fields once and filling the whole
model in one line is a huge help.

![Mass assignment](https://api.memegen.link/images/zero-wing/All_your_columns_are_belong_to_us.png)

### 7. ↪️ Back to the list, newest first

After saving, the user goes back to the posts list. `redirect()` wants an address, but we have
route names:

```php
return redirect()->route('posts.index');
```

The new posts were on the last of over sixty pages. Sorting fixes that: `orderBy('created_at',
'desc')` (ascending `asc` is the default), or shorter, `latest()`, which means the same:

```php
$posts = Post::latest()->paginate(16);
```

Now a new post is right at the top. Next time: editing posts.

## ✅ Takeaways

1. **Fields need a `name`**, or nothing is sent.
2. **A new form request's `authorize()` says no** until you decide who may; leave a `@todo`.
3. **Every form gets `@csrf`.**
4. **Rules in the form request**, errors back in the view with `@error` and `$message`.
5. **Never trust user input**: fill models from `validated()`, and list `$fillable` on the model.
6. **`redirect()->route()`** after saving; `latest()` for newest first.
