### 1. 🛠️ Installing Laravel

Anyone who still did not have Composer installed it first
(<https://getcomposer.org/download/>, and then a new terminal). The Laravel docs
(<https://laravel.com/framework/docs>) offer a few ways to install; we already have PHP and
Composer, so the Laravel installer is enough:

```
composer global require laravel/installer
```

`global` means it is installed for the user, not into the current folder. Then, **anywhere
except inside the learnphp folder**:

```
laravel new mm24blog
```

The installer asks a few questions: no starter kit this time, Pest for testing, and yes to the
AI tooling (Laravel Boost). The first attempt stopped with a "missing from your system" message:
Laravel needs a couple more PHP extensions than learnphp did. In `php.ini` (the one in the PHP
folder, around line 900) the needed `extension=` lines got their `;` removed.

Running `laravel new` again then says the application already exists, because the first run had
half-built it. The folder was deleted and the command run again. `rm -rf` deletes permanently
with no recycle bin: read the command three times before pressing Enter.

### 2. 🗂️ A tour of the project

A Laravel project looks scary: lots of folders, lots of files. Most of it is familiar, because
learnphp was designed to look like a small Laravel.

| Folder | What it is | learnphp equivalent |
|---|---|---|
| `app/` | our code: `Http/Controllers` (with an abstract base `Controller`), `Models` (a `User` model is already there), `Providers` | `src/` |
| `bootstrap/` | **not** the CSS framework: the code that pulls the application together and starts it, like pulling your boot laces tight before leaving the house | `public/index.php` setup |
| `config/` | settings for everything: database, file system, mail, sessions. Many values come from `env()` | the DB settings in code |
| `database/` | `migrations`, `factories`, `seeders`, and the SQLite file | `database.sqlite` |
| `public/` | `index.php` (the front controller), `.htaccess`, `favicon.ico`, `robots.txt` | `public/` |
| `resources/` | `css`, `js` and `views` (Blade templates) | `views/` |
| `routes/` | `web.php` for pages, `console.php` for commands | `routes.php` |
| `storage/` | uploaded files (`app/private`, `app/public`), cache, sessions, compiled views, logs | `public/uploads` |
| `tests/` | `Unit` and `Feature` tests | none |
| `vendor/` | Composer packages, many more than our one | `vendor/` |

`app/Providers` holds **service providers**: they let you set up and change how the application
works when it starts. 99% of the time you do not touch them.

### 3. 🧱 Migrations, factories, seeders (first look)

The `database` folder has three parts we never had in learnphp: there, the database structure
and its data only lived in the `.sqlite` file. Here:

- **Migrations** describe the database structure in code. Each has an `up()` that makes a change
  and a `down()` that undoes it. The users migration, for example:

  ```php
  Schema::create('users', function (Blueprint $table) {
      $table->id();
      $table->string('name');
      $table->string('email')->unique();
      $table->timestamp('email_verified_at')->nullable();
      $table->string('password');
      $table->rememberToken();
      $table->timestamps();
  });
  ```

  The column types are Laravel's own names; it translates them to whatever the real database
  supports.
- **Factories** create model instances filled with fake data.
- **Seeders** call the factories to fill the database.

`database/.gitignore` contains `*.sqlite*`, so the database file itself stays out of git. The
structure travels as migrations instead. More on all three soon.

### 4. 🌐 `public/` and `routes/`

- `public/index.php` loads Composer's autoloader and boots the app. Never needs changing.
- `public/.htaccess` is for Apache: if the requested file does not exist, send the request to
  `index.php`. The same thing our `public/index.php` did for the PHP built-in server.
- `favicon.ico` is a 0 byte placeholder.
- `robots.txt` tells search engine crawlers (Google's "spiders") which pages not to visit. It is
  a polite agreement, not security: bad bots ignore it, and for hackers it is a handy list of the
  interesting pages.

`routes/web.php` is our `routes.php`:

```php
Route::get('/', function () {
    return view('welcome');
});
```

A closure for now, but it can point at a controller method just like ours did.

### 5. 🗃️ `resources/`, Blade and `storage/`

Views are `.blade.php` files: Blade is Laravel's template language, which makes views shorter
to write (`{{ }}` instead of `<?= ?>` and so on). Blade has to be turned into plain PHP first, so
Laravel compiles each view once and keeps the result in `storage/framework/views`; next time
the page loads it skips that work. Sessions are not left in PHP's temp folder either: Laravel
manages them itself (`storage/framework/sessions` for the file driver; this project's
`.env.example` says `SESSION_DRIVER=database`). Errors go to `storage/logs`.

### 6. 🧪 Tests (why they exist)

- **Unit tests** test the smallest unit, usually one function: give `add()` 2 and 2, expect 4;
  give it letters, expect an error.
- **Feature tests** test a whole feature: register a user, try to log in, check that it worked.

The point: in a big system you cannot click through everything after every change, and something
you did not touch (login, registration) can still break because of a setting changed somewhere
else. Tests run automatically, before each commit or deploy. AI can write tests too, but check
what it wrote.

### 7. 🔑 `.env`: never in git

Most values in `config/` come from `env()`, which reads environment variables. Every system has
them, but for a development machine with several Laravel apps it makes no sense to set them for
the whole system, so the project has its own `.env` file: simple `KEY=value` lines.

`.env` holds passwords, keys and server addresses, so it is in `.gitignore` and **never** goes
into git, not even a private repo: you cannot guarantee the repo stays private forever, and git
history remembers everything. `.env.example` is the template that does go into git; a new
`.env` is made from it.

If a secret does leak: change the passwords or keys immediately (or tell whoever owns them, right
away). Bots scan public GitHub repos for keys automatically, and a leaked key can be used for
crypto mining within minutes.

### 8. 📄 The rest of the files

- `.editorconfig`: an open standard telling editors about indentation, line endings and so on.
- `.gitattributes`: tells git how to treat certain file types.
- `artisan`: Laravel's command line tool, a PHP file without the `.php`. Used as `php artisan ...`
  and very powerful.
- `composer.json` / `composer.lock`: like learnphp's, plus handy scripts (`setup`, `dev`, `test`).
- `package.json`: Vite and Tailwind, to build the CSS and JS.
- `phpunit.xml`: test settings.
- `AGENTS.md`, `CLAUDE.md`, `boost.json`, `.mcp.json`, `.claude/skills`: guidelines for AI tools,
  from Laravel Boost. Useful, but get to know the terminology yourself before letting AI do
  everything.

### 9. 🥟 Bun and running the app

The project went to GitHub as is, untouched, as the first commit:
<https://github.com/Kasparsu/mm24blog>.

For the frontend tooling we use **Bun** (<https://bun.com/>) instead of npm. Everything that
worked with Node and npm works with Bun, it is much faster, and it has things built in that npm
needs extra packages for. Commands are almost the same: `bun install`, `bun run build`. It is
installed with the command from its home page, in a new terminal.

```
bun install
bun run build
composer run dev
```

`bun install` created `bun.lock` (the second commit). `composer run dev` starts several things at
once and prints two addresses: Vite on `localhost:5173` (it rebuilds the CSS and JS as files
change) and the app itself on `localhost:8000`. **Open 8000.** Laravel's welcome page links to
the docs and to Laracasts (<https://laracasts.com/>): good quality videos on Laravel and web
development, a lot of them free.

## ✅ Takeaways

1. **`composer global require laravel/installer`, then `laravel new`**, outside other projects.
2. **Most of Laravel's structure is familiar**: `app` is `src`, `routes/web.php` is `routes.php`, `public/index.php` is the front controller.
3. **Migrations carry the database structure in code**, with `up()` and `down()`; the `.sqlite` file stays out of git.
4. **`.env` never goes into git.** A leaked key gets changed immediately.
5. **`composer run dev` starts the app**: open `localhost:8000`, not Vite's port.
