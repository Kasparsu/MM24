## 🗂️ Topics Covered

### 1. 🎨 Why We're Using Someone Else's Front End

You could write all the HTML and CSS yourself, and you can, more or less. But it isn't a good
use of time here, and it isn't how the job usually works.

**In practice, working on the back end, the markup arrives from someone else.** A designer or
a front-end developer hands you a finished page, or you start from a template. The skill that
actually matters is **reading markup you didn't write** and turning it into a working
server-side template.

So: take a ready-made template, understand it, and make it dynamic.

---

### 2. 🅱️ Bootstrap

**Bootstrap** is the CSS framework used for this. The site has a large set of ready-made
**Examples**: full page layouts you can download and adapt.

| Link | What it is |
|---|---|
| <https://getbootstrap.com/> | Bootstrap |
| <https://getbootstrap.com/docs/5.3/examples/> | Ready-made example pages |

**Downloading one** gives you a `.zip`.

> ⚠️ **Extract it properly.** Windows lets you double-click into a zip and browse it as if it
> were a folder, but files inside cannot be moved or served from there. Right-click →
> **Extract All** first. Skipping this is the usual reason "nothing works".

**What comes in the blog example:**

```
index.php
blog.css
assets/
  brand/bootstrap-logo.svg
  dist/css/bootstrap.min.css
  dist/css/bootstrap.rtl.min.css
  dist/js/bootstrap.bundle.min.js
  js/color-modes.js
```

**On `bootstrap.rtl.min.css`**: `rtl` is **right-to-left**. A separate stylesheet exists
because languages such as Arabic and Hebrew are written right to left, and a whole layout has
to mirror for them.

`color-modes.js` is what drives the light/dark theme switcher in the template.

### 3. ✂️ Splitting the Template into Partials

The downloaded `index.php` is one file of roughly **750 lines**. Perfectly functional, and
unmanageable.

The fix is to cut it into **partials**: one file per section of the page:

```
partials/
  header.php       <head>, meta, stylesheets
  nav.php          the navigation bar
  themeselect.php  the light/dark switcher
  hero.php         the big banner
  featured.php     the featured-post block
  posts.php        the list of blog posts
  sidebar.php      the side column
  footer.php       the footer
```

`index.php` shrinks from ~750 lines to about **8**: it just pulls the pieces in, in order.

**Why this is worth doing:**

| Benefit | Why it matters |
|---|---|
| You can find things | "The nav is broken" → open `nav.php`, not line 213 of 750 |
| Reuse | The same header and footer serve every page on the site |
| One place to change | Edit the nav once, and every page that includes it updates |

> 🧠 This is the same instinct as putting repeated code in a function: don't say the same
> thing twice, and keep each piece small enough to hold in your head.

## ✅ Takeaways

1. **Reading markup you didn't write is the real back-end skill.** The design usually arrives
   from someone else.
2. **Extract the zip.** Browsing inside it is not the same as unpacking it.
3. **`rtl` stylesheets mirror the layout** for right-to-left languages.
4. **Split a long template into partials.** One file per section, `index.php` just assembles
   them.
