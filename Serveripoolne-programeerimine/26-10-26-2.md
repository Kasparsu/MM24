### 1. 🐌 Slugs for users

The morning lesson explained why `/user/2` is not a great address. Now the `spatie/laravel-sluggable`
package does the work. Three pieces were needed.

**A column for it.** The slug is stored in the `users` table and has to be unique, since it now
identifies the user in the URL. The project is still in development, so the column went straight
into the original users migration and the database was rebuilt:

```php
$table->string('slug')->unique();
```

**Telling the model where the slug comes from.** The package version used here is configured with
a PHP attribute on the class, the same style the model already uses for `Fillable` and `Hidden`:

```php
use Spatie\Sluggable\Attributes\Sluggable;

#[Fillable(['name', 'email', 'password'])]
#[Hidden(['password', 'remember_token'])]
#[Sluggable(from: 'name', to: 'slug')]
class User extends Authenticatable implements MustVerifyEmail
```

When a user is created, the package takes `name`, turns it into a URL friendly string and saves
it into `slug`. If two users share a name, it adds a number to keep the slug unique.

**Using the slug in routes.** Route model binding looks models up by `id` by default. Overriding
`getRouteKeyName()` changes that for the whole model:

```php
public function getRouteKeyName(): string
{
    return 'slug';
}
```

Nothing else had to change: `route('user', $post->user)` on the post card now puts the slug into
the link, and the `/user/{user}` route finds the user by slug. Posts could get the same treatment
from their titles, and tags too (which is where the next task came from).

### 2. 🔇 Why the slugs stayed empty: `WithoutModelEvents`

After reseeding, the slugs did not appear. The reason was a line Laravel puts into
`DatabaseSeeder` by default:

```php
//use WithoutModelEvents;
```

`WithoutModelEvents` turns off model events while seeding, which makes seeding faster. But the
slug package works exactly through a model event: it fills in the slug when the model is being
saved. With events off, the package never ran, and the seeded users had no slugs. Commenting the
trait out fixed it.

Worth remembering: if a package "does something automatically when a model is saved", it is
listening to model events, and anything that disables them disables the package too.

![Sudden clarity](https://api.memegen.link/images/scc/WithoutModelEvents_means_no_model_events/so_the_slug_package_never_even_ran.png)

## ✅ Takeaways

1. **A slug needs a unique column**: `$table->string('slug')->unique()`.
2. **`#[Sluggable(from: 'name', to: 'slug')]`** on the model makes spatie/laravel-sluggable fill it from the name.
3. **`getRouteKeyName()` returning `'slug'`** makes route model binding and `route()` use the slug instead of the id.
4. **`WithoutModelEvents` in a seeder switches off model events**, and with them every package that works on save.
5. **Next**: the same slugs for tags and posts are an easy follow up.
