## 🗂️ Topics Covered

> 🔄 The morning ended with the View link sending an id. This lesson finds the article by
> that id, and then uses the same idea for editing and deleting. The admin side can now do
> everything with an article.

### 1. 🔎 `find()`: one row by id

```php
public function find($table, $class, $id) {
    $sql = "SELECT * FROM $table WHERE id=$id";
    $result = $this->conn->query($sql);
    $result->setFetchMode(PDO::FETCH_CLASS, $class);
    return $result->fetch();
}
```

Almost a copy of `all()`, with two changes:

- **`WHERE id=$id`**: all columns, but only the matching row.
- **`fetch()` instead of `fetchAll()`**: an id can match at most one row, so there is no
  point getting an array back. `fetch()` returns a single object, or `false` if nothing
  was found.

The model side is the usual one-liner, so `Article::find(5)` works:

```php
public static function find($id) {
    $db = new DB();
    return $db->find(static::$table, static::class, $id);
}
```

### 2. 👁️ The view page and a missing id

```php
public function view() {
    $article = Article::find($_GET['id']);
    if($article) {
        view('articles/view', compact('article'));
    } else {
        echo 404;
    }
}
```

Typing an id that does not exist (say 1000) into the address bar gives `false`, so the
controller has to check before handing it to a view. `views/articles/view.php` shows one
article as a two-column table: the field name in a `<th>`, the value in a `<td>`.

### 3. ✏️ The edit form, prefilled

The create form was copied to `views/articles/edit.php`, with two changes: it posts to
`/admin/articles/edit?id=...`, and every field shows the current value.

```php
<input value="<?= $article->title ?>" name="title" type="text" class="form-control" id="title">
```

```php
<textarea name="body" class="form-control" id="body" rows="12"><?= $article->body ?></textarea>
```

An `<input>` takes its value from the `value` attribute. A `<textarea>` does not have one:
the value is whatever sits between the tags. That means **no spaces or line breaks between
the tags and the PHP**, because those count as content. With the code nicely indented,
every save stores the extra whitespace, and the next edit adds more.

The date field showed one more wrinkle: rows added by hand in the database had a date and
a time, while rows made through the form only have a date, and a date input only fills in
the second kind.

### 4. 🛠️ UPDATE: building `SET` from the fields

```php
public function update($table, $fields, $id) {
    $updateText = '';
    foreach($fields as $name=>$value) {
        $updateText .= "$name='$value', ";
    }
    $updateText = substr($updateText, 0, -2);
    $sql = "UPDATE $table
            SET $updateText
            WHERE id=$id";
    $this->conn->exec($sql);
}
```

The loop writes `name='value', ` for each field. The last one leaves a trailing `, ` that
SQL refuses, so `substr($updateText, 0, -2)` cuts it off: start at 0, and a negative length
means "everything except the last 2 characters". As in the morning, the SQL was printed and
checked before letting it run.

### 5. 🤔 Insert or update? Let the id decide

```php
public function save() {
    $fields = get_object_vars($this);
    unset($fields['id']);
    $db = new DB();
    if($this->id) {
        $db->update(static::$table, $fields, $this->id);
    } else {
        $db->insert(static::$table, $fields);
    }
}
```

A new object has no id (the database hands it out). An object that came from `find()`
does. So the same `save()` covers both cases, and `update()` in the controller looks
almost exactly like `store()`: find the article, overwrite the fields, save, redirect.

### 6. 🗑️ Delete

```php
public function delete() {
    $db = new DB();
    $db->delete(static::$table, $this->id);
}
```

```php
Router::get('/admin/articles/delete', [ArticlesController::class, 'delete']);
```

Same pattern once more: a link with `?id=`, find the article, call `delete()` on it,
redirect back to the list.

### 7. 🧩 CRUD

A system that can **C**reate, **R**ead, **U**pdate and **D**elete records is called a
**CRUD**. Most admin panels are exactly this, repeated per table. HTTP actually has more
request types than GET and POST for these jobs (PUT, PATCH, DELETE), which will come up
later. Next lesson: logging in.

## ✅ Takeaways

1. **`fetch()` for one row, `fetchAll()` for many**, and check for `false` before using the result.
2. **Inputs use `value`, textareas use their content**, so keep the PHP tight against the tags.
3. **`substr($text, 0, -2)`** trims the trailing comma from a built-up list.
4. **The id decides insert or update.** One `save()` for both.
5. **Create, Read, Update, Delete = CRUD**, the backbone of every admin panel.
