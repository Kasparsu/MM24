### 1. 📦 Composer and Packagist

Composer (<https://getcomposer.org/>) is to PHP what npm was to Node: it downloads packages
(code we did not write) into the project and keeps track of them. Packages live on Packagist
(<https://packagist.org/>). Do not mix it up with *packagist.com*, which is the paid version
for private packages.

Need image processing, QR codes, PDFs, a router? Someone has almost certainly written it
already. Even our own Router has dozens of ready-made alternatives on Packagist (AltoRouter,
for example, works quite like ours).

Winget does not have Composer, so on Windows it is installed with `Composer-Setup.exe` from
the download page (<https://getcomposer.org/download/>). The installer has to find our PHP;
"install only for me" made it find it. It also creates a `php.ini` if there is none and turns
on a few extensions it needs itself. Afterwards: a **new** terminal (the old one does not know
the new command yet) and `composer --version`.

### 2. 🧾 `composer init`

`composer init` in the project folder asks a series of questions, most of which can be
answered with Enter:

- **name**: `vendor/project`, often the GitHub username and the project name. It only really
  matters for libraries that others install.
- **description**, **author** (taken from the git config if it is set), **minimum stability**:
  can be left empty.
- **license**: with no license nobody may legally use your code, the same as with a photo you
  took. The project got **WTFPL**: do whatever you want with it.
- **dependencies**: skipped for now, packages get added by hand right after.
- **PSR-4 autoload**: yes, and then it generates the autoload files.
- **add `vendor` to `.gitignore`**: yes.

The result:

```json
{
    "name": "kaspar.martin.suursa/learnphp",
    "type": "project",
    "license": "WTFPL",
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    },
    "authors": [ ... ],
    "require": {
        "symfony/var-dumper": "^8.1"
    }
}
```

`composer.json` is the `package.json` of PHP. `vendor/` is the `node_modules` of PHP: a million
small files that never go into git, because they can always be downloaded again:

```
/vendor/
```

### 3. 🔁 Composer's autoloader instead of ours

Every package needs autoloading too, and nobody wants to write an autoloader per package, so
Composer provides one. And if it is there anyway, our own code can use it as well. Ours worked,
but it had a hundred small bugs that only show up when something goes wrong.

`composer init` suggested its own namespace, so the mapping was changed to the one the project
already uses: `App\` lives in `src/`. Changing `composer.json` does **not** regenerate the
autoload files, so after the edit:

```
composer dump-autoload
```

In `public/index.php` our `spl_autoload_register` went and Composer's autoloader came in:

```php
-spl_autoload_register(function ($class){
-    $class = substr($class,4);
-    $class = str_replace('\\', '/', $class);
-    require_once __DIR__ . "/../src/$class.php";
-});
+require __DIR__ . '/../vendor/autoload.php';
```

`index.php` is in `public/`, so the path goes one folder up. Everything kept working without any
other change.

### 4. 📐 PSR standards

Why do classes and folders start with capital letters, and why do namespaces follow the folders?
Because the project quietly followed **PSR-4**, the autoloading standard from PHP-FIG
(<https://www.php-fig.org/psr/>, <https://www.php-fig.org/psr/psr-4/>).

PHP itself lets you name and format things however you like. The PSRs are strong
recommendations, so that many people can work on the same code:

- Mixed styles in one codebase are hard to read.
- Worse: if every developer's editor auto-formats to their own style, every commit is full of
  "changes" that are just styles overwriting each other, and the one real change is lost
  somewhere among them.

PSR-1 and PSR-12 cover the coding style, PSR-4 the autoloading. Because our autoloader followed
PSR-4 from the start, switching to Composer's changed one line.

![PSR-4](https://api.memegen.link/images/success/Followed_PSR--4_from_day_one/Switched_to_Composer's_autoloader_by_changing_one_line.png)

### 5. 🔍 `symfony/var-dumper`

First real package (<https://packagist.org/packages/symfony/var-dumper>):

```
composer require symfony/var-dumper
```

Packages are named `vendor/name`, so a little more to type than with npm. var-dumper adds two
functions: `dump()` and `dd()`. Those were the names of our own helpers, on purpose, and that is
also why ours had to go: two functions with the same name conflict.

```php
-function dump(...$vars) {
-    echo '<pre>';
-    var_dump(...$vars);
-    echo '</pre>';
-}
-
-function dd(...$vars) {
-    dump(...$vars);
-    die;
-}
```

A test on the U.S. page:

```php
public function us()
{
    $articles = Article::all();
    dump($articles);
```

The output is dark themed, coloured by type, and long or nested values can be folded open and
closed. Much nicer than our `<pre>` and `var_dump`.

### 6. 🔒 `composer.lock`, `composer install` vs `composer require`

`composer.json` says `^8.1`: anything from 8.1 up to, but not including, 9.0. `composer.lock`
records exactly what was installed (var-dumper and the `symfony/polyfill-mbstring` package it
needs itself), so another computer gets exactly the same versions. Same idea as
`package-lock.json`.

To show what a fresh clone looks like, the `vendor` folder was deleted. The site then fails
with an error about `vendor/autoload.php` not being found. Remember that error: it means
"you have not installed the packages yet". The fix:

| Command | When |
|---|---|
| `composer require vendor/package` | add a **new** package |
| `composer install` | install everything already listed (after a clone or a pull) |

![composer.lock](https://api.memegen.link/images/older/composer.lock_pins_symfony~svar--dumper_v8.1.7/An_older_version,_sir,_but_it_checks_out.png)

Before committing: if git does not know who you are on this computer, set `user.name` and
`user.email` with `git config --global`, or the commit will fail.

## ✅ Takeaways

1. **Composer is npm for PHP**, Packagist is its package registry.
2. **`vendor/` never goes into git**; `composer install` brings it back.
3. **Composer's autoloader works for our own code too**: map `App\` to `src/` and run `composer dump-autoload` after changing it.
4. **PSR standards keep shared code readable** and commits free of style noise.
5. **`require` adds a new package, `install` restores the listed ones** at the versions in `composer.lock`.
