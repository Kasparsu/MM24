## 🗂️ Topics Covered

> At the end the card markup moves into one partial shared by the home page and the post page.

### 1. 🔄 After pulling: install, migrate, your own password

When you pull the project and `composer.lock` or `package-lock.json` has changed, someone added
or updated packages: run `composer install` and `npm install` before anything else. Changed
migrations or seeders mean the database has to be rebuilt (`php artisan migrate:fresh --seed`).

The seeder from last time creates a default user from `.env` (`DEFAULT_USER_NAME`,
`DEFAULT_USER_EMAIL`, `DEFAULT_USER_PASSWORD_HASH`), so you do not have to register again after
every fresh migration. The password goes there as a hash, not as plain text. You can make the
hash in `php artisan tinker` with `Hash::make(...)`, and put it in `.env` in double quotes, since
a bcrypt hash is full of `$` signs. Keep in mind that tinker remembers its history, so the plain
password you typed stays there.

### 2. 🗂️ Only my posts in the admin

The posts seeder gives every one of the 1000 posts a random user, so each user owns some posts.
The admin list still showed all of them. A normal user (not an admin) should only see their own.

Last lesson both models got their relationship (`Post` belongs to a `User`, a `User` has many
`posts`). The logged in user comes from `Auth::user()` (or the `auth()` helper). Then the
difference between the property and the method:

- `$user->posts` (no brackets) runs the query right away and gives a collection of all the posts.
- `$user->posts()` (with brackets) gives the **query**, not yet sent to the database. More can be
  added to it: ordering, filtering, pagination.

```php
use Illuminate\Support\Facades\Auth;
...
public function index()
{
    /** @var App\Models\User $user */
    $user = Auth::user();
    $posts = $user->posts()->latest()->paginate(16);
    return view('posts.index', compact('posts'));
}
```

The `@var` comment is only for the editor. `Auth::user()` is declared to return a generic
authenticatable user, so the editor does not know it has a `posts()` method and underlines it,
even though the code works. The comment tells it the real class. (To be safe, write the class
fully qualified, `\App\Models\User`, or import it with `use`.)

### 3. 🛡️ Protecting the admin with `auth` middleware

Log out and open `/admin/posts`: an error, because `Auth::user()` is `null` and `null` has no
`posts()`. The admin pages must only be reachable by a logged in user.

That is what **middleware** is for: a layer between the route and the controller that runs
before the request reaches the controller, and can do the same check for a whole group of
routes. The `auth` middleware checks whether the user is logged in; if not, it redirects to the
login page. Breeze's own routes already use it (the dashboard with `['auth', 'verified']`, the
profile routes in a `middleware('auth')` group). For our resource route it goes on the end:

```php
Route::resource('/admin/posts', PostController::class)->middleware('auth');
```

Now `/admin/posts` sends a guest to the login page, and after login the list opens.

### 4. 🙈 Hiding the Admin menu with `@auth`

There is no point showing the Admin menu to someone who cannot use it. The nav already showed
the user dropdown or Login/Register depending on login state; the Admin item now gets the same
treatment, in both the mobile and the desktop menu:

```html
@auth
    <li>
        <details>
            <summary>Admin</summary>
            <ul class="p-2 bg-base-100 w-40 z-1">
                <li><a href="{{ route('posts.index') }}">Posts</a></li>
                <li><a>Submenu 2</a></li>
            </ul>
        </details>
    </li>
@endauth
```

Hiding the link is not security. Anyone can type `/admin/posts` into the address bar. The
middleware is what really protects the page; hiding the link only keeps the menu tidy.

![Hiding is not security](https://api.memegen.link/images/rollsafe/Can_not_open_the_admin_page/if_the_menu_link_is_hidden.png)

### 5. ✍️ Creating a post: the author comes from the session

Adding a post broke: since last lesson the `posts` table needs a `user_id`, and the form does
not send one. And it should not. A typical beginner idea is to put the user's id in a hidden
form field, but the user controls everything the browser sends: a hidden field can be changed
in the dev tools, or a request can be made without the form at all. **Never trust user input**
for things like this.

We already know who is logged in, so the controller sets the author before saving.
`associate()` sets the `belongsTo` relationship from a model:

```php
$post = new Post($request->validated());
$post->user()->associate(Auth::user());
$post->save();
```

![Hidden user_id](https://api.memegen.link/images/philosoraptor/If_user__id_comes_from_a_hidden_field/who_really_wrote_the_post~q.png)

The new post appeared in the admin list, but not on the home page, which still listed posts in
id order. The home page now shows the newest first:

```php
$posts = Post::latest()->simplePaginate(16);
```

### 6. 🕒 Showing when a post was written: `diffForHumans()`

The cards did not say when a post was written. Printing `$post->created_at` gives a full date and
time, which has two problems. It does not say much at a glance, and it was three hours off: the
database stores the time in UTC, and Estonia is UTC+3 right now.

Ways around the time zone:

- Set Laravel's time zone (in `config/app.php`) to Tallinn. Fine for a purely Estonian site, but
  a visitor from another country would see the wrong time again. Storing UTC and converting when
  showing is the usual approach.
- Let JavaScript convert it using the visitor's own computer clock.
- Show a **relative** time instead: "5 minutes ago", "3 days ago". The time zone stops
  mattering, and it is what most sites show anyway.

Most languages have some date handling built in, but there is usually one popular library for
working with dates. In PHP that is **Carbon**
(<https://carbonphp.github.io/carbon/guide/date-time-manipulation/difference-for-humans.html>),
and Laravel already includes it: `created_at` is a Carbon object, so no install is needed.
`diffForHumans()` shows seconds until a minute has passed, then minutes, then hours, then days,
and so on:

```html
<span class="text-base-content/70">{{ $post->created_at->diffForHumans() }}</span>
```

![Time zones](https://api.memegen.link/images/harold/Post_created_at_06:38/It_is_09:38_in_Tallinn.png)

### 7. 🧩 One card partial for both pages

The home page card got the author and the date, but the single post page has its own copy of the
card, which got neither. Two copies of the same markup always drift apart. The card moved to
`resources/views/partials/post-card.blade.php`, and both pages just include it:

```html
@include('partials.post-card')
```

The two cards are not identical, though. The home page shows the snippet and a Read more button,
the post page the whole text and no button. The partial tells them apart by whether a `$posts`
list exists: the home page has one, the post page only has a single `$post`.

```html
<h2 class="card-title">{{ $post->title }}</h2>
@isset($posts)
    <p>{{ $post->snippet }}</p>
@else
    <p>{!! $post->displayBody !!}</p>
@endisset
<span class="text-base-content/70">{{ $post->user->name }}</span>
<span class="text-base-content/70">{{ $post->created_at->diffForHumans() }}</span>
<div class="card-actions justify-end">
   @isset($posts)
       <a href="{{ route('post', $post) }}" class="btn btn-primary">@lang('Read more')</a>
   @endisset
</div>
```

Now the post page shows the author and the date too, and any later change to the card happens in
one place.

## ✅ Takeaways

1. **Pulled and `composer.lock` or `package-lock.json` changed?** Run `composer install` and `npm install`.
2. **`$user->posts` is the result, `$user->posts()` is the query**: only the second can take `latest()` or `paginate()`.
3. **`auth` middleware protects routes**; `->middleware('auth')` on the resource route covers all seven.
4. **`@auth` hides menu items**, but hiding a link is not security.
5. **Never take the author from the form.** `$post->user()->associate(Auth::user())` in the controller.
6. **Dates are stored in UTC**; `diffForHumans()` (Carbon, built into Laravel) sidesteps time zones.
7. **Shared markup goes in a partial**, with `@isset` for the small differences.
