### 2. 💻 Setting Up the Machines — `winget`

New classroom, fresh machines, so everything gets installed from scratch. Windows ships
PowerShell but not a Bash-style shell, and for server work later on a Bash-like environment is
what you want.

Rather than downloading installers and clicking through wizards, everything is done from the
command line with **winget**.

**Visual Studio Code:**
```powershell
winget install vscode
```
On first run winget asks for consent to install from the Microsoft Store — say yes, and it
won't ask again for that account. Nothing to click through after that.

### 3. 🔧 Installing Git — and the Options That Matter

Git needs to be installed **interactively**, because a few of its setup options cannot be
changed afterwards:

```powershell
winget install --interactive Git.Git
```

**The options worth getting right:**

| Option | Set it to | Why |
|---|---|---|
| Default editor | **Visual Studio Code** | The default is Vim. If Git ever drops you into an editor, you want one you can leave. |
| **Add a Git Bash profile to Windows Terminal** | ✅ Yes | **This is the one you cannot fix later.** It's what puts Git Bash in the terminal's dropdown. |
| Default branch name | **`main`** | Rather than `master` |

> ⚠️ Already installed Git without ticking those? You don't have to uninstall — re-run with
> `--force` and it will reinstall with the options you pick.

**On `main` vs `master`:** the rename happened because `master` carries an unpleasant
connotation. `main` is now the default nearly everywhere, so matching it avoids friction.

**After installing:** close the terminal and open a new one — the Git Bash profile only shows
up in a fresh window. Then set it as the default profile in Windows Terminal settings, so new
tabs open in Bash rather than PowerShell.

### 5. ⚙️ Configuring Git — The Step Everyone Forgets

```bash
git config --global user.name "Kaspar Martin Suursalu"
git config --global user.email "your.email@example.com"
```

**This is per computer, not per project.** Run it once on each machine you use — the school
PC, a different classroom, your machine at home. It is **not** a login; it only tells Git what
name and address to stamp on commits.

**Why the email matters:** use the same address you sign in to GitHub with. Then GitHub can
match "the account with this email" to "the commit with this email" and attribute the commit
to you. Nothing breaks if it's wrong — your commits just won't be linked to your profile.

> 🎓 **Add a personal email to your GitHub account as well.** GitHub lets you register several
> addresses and switch which is primary. Your school address will stop working after you
> graduate; if it's the only one on the account, you lose access to your own projects and
> your password reset. Add a private address now.

## ✅ Takeaways

1. **Backend first, then frontend, then join them.** The end goal is a front end talking to an
   API you wrote yourself.
2. **`winget install` beats hunting for installers.**
3. **Install Git interactively** — the Git Bash terminal profile can't be added afterwards.
   `--force` reinstalls if you missed it.
4. **`git config --global` is once per machine**, and it isn't a login.
5. **Put a personal email on your GitHub account** before your school one expires.
