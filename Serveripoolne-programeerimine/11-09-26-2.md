### 1. 🏗️ `__construct`: Setting Up an Object

Up to now properties were assigned one by one after creating the object. A **constructor**
runs automatically when the object is made:

```php
class Box {
    public function __construct(private $w, private $h, private $l) {
        var_dump('Box was created!');
    }

    public function volume() {
        return $this->w * $this->h * $this->l;
    }
}

$box1 = new Box(1, 2, 3);   // prints "Box was created!"
```

Note what's happening in the parameter list: **constructor property promotion**. Writing
`private $w` as a *parameter* declares the property, sets its visibility, and assigns it, all
in one go. The longhand equivalent would be a `private $w;` declaration plus
`$this->w = $w;` in the body.

### 2. ✨ Magic Methods

Methods whose names start with `__` are **magic**: PHP calls them for you when something
particular happens.

```php
public function __set($name, $value) { var_dump($name, $value); }
public function __get($name)         { var_dump($name); return 'YOLO'; }
public function __invoke()           { var_dump('Im a function'); }
public function __call($name, $args) { var_dump($name, $args); }
public function __toString()         { return "Im a box with W: $this->w H: $this->h L: $this->l"; }
public function __destruct()         { var_dump('Box was destroyed!'); }
```

| Magic method | Fires when… | Demonstrated by |
|---|---|---|
| `__construct` | The object is created | `new Box(1,2,3)` |
| `__set` | You write a property that **isn't accessible** | `$box1->color = 'hello';` |
| `__get` | You read a property that isn't accessible | `var_dump($box1->lolollol);` → `'YOLO'` |
| `__invoke` | You call the **object itself** like a function | `$box1();` |
| `__call` | You call a method that doesn't exist | `$box1->hello(1, 'aasda', 'azczxc');` |
| `__toString` | The object is used as a string | `echo $box1;` |
| `__destruct` | The object is destroyed | see below |

**`__destruct` is the interesting one.** An object is destroyed when nothing refers to it any
more:

```php
function lol() {
    $box4 = new Box(4, 4, 5);
}
lol();          // created, then destroyed the moment the function ends

$box1 = new Box(1, 2, 3);
$box1 = 1;      // the Box has nothing pointing at it now → destroyed
```

> 💡 `__get`/`__set`/`__call` let an object respond to things it doesn't actually have.
> Powerful, and easy to abuse: the full list is in the manual.

### 3. 🏛️ `static`: Belonging to the Class, Not the Object

A `static` property or method belongs to the **class itself**, shared by every instance:

```php
class Box {
    public static $count = 0;

    public function __construct(private $w, private $h, private $l) {
        self::$count++;      // every new Box bumps the shared counter
    }

    public static function me() {
        var_dump(self::class);
        var_dump(static::class);
    }
}

class MetalBox extends Box {}
```

**Reached with `::` instead of `->`,** because there's no object involved:

```php
Box::$count = 1;
Box::me();
MetalBox::me();
var_dump(Box::$count);
```

**`self` vs `static`:**

| | Resolves to |
|---|---|
| `self::class` | The class where the code was **written**: always `Box` |
| `static::class` | The class it was actually **called on**: `Box` or `MetalBox` |

So `MetalBox::me()` prints `Box` then `MetalBox`. That difference (late static binding) is
exactly why both keywords exist.

**The classic use** is the instance counter above: `$count` is not per-box, it's per-class, so
it can count how many boxes have ever been made.

### 4. 🔌 Interfaces: Agreeing on a Shape

The most important idea of the session.

```php
interface Logger {
    public function log($message);
}
```

An interface is a **contract**: any class that says `implements Logger` must provide a
`log($message)` method. The interface has no bodies, only the required shape.

```php
class ConsoleLogger implements Logger {
    public function log($message) {
        echo "$message\n";
    }
}

class NothingLogger implements Logger {
    public function log($message) {
        // deliberately does nothing
    }
}

class FileLogger implements Logger {
    public function log($message) {
        $file = fopen('log.txt', 'a');
        fwrite($file, "$message\n");
        fclose($file);
    }
}
```

**Why this matters**: the consuming code:

```php
class Job {
    public function task(Logger $logger) {
        for ($i = 0; $i < 10; $i++) {
            // some work is done (video processing or whatever)
            $logger->log("Task $i was done!");
        }
    }
}

$job = new Job();
$logger = new FileLogger();
$job->task($logger);
```

`Job::task()` type-hints **`Logger`, not a specific class**. It doesn't know or care whether
logging goes to the console, to a file, or nowhere. Swap the object you pass in and the
behaviour changes with no edit to `Job`.

> 🧠 Note the comment structure in the example: `Job` and the interface are the **library**;
> `FileLogger` is **user code**. The library author never saw `FileLogger`, yet it plugs in:
> because both sides agreed on the interface. That's the whole point.

Running it writes `log.txt` with `Task 0 was done!` … `Task 9 was done!`.

### 5. 🖼️ PHP as a Templating Language

The shift from "programs that print" to "pages that get served".

A `.php` file is **HTML with escapes into PHP**. Everything outside `<?php … ?>` is sent to
the browser untouched.

```php
<?php
$name = 'Kaspar';
$coinFlip = rand(0, 1);
?>

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <h1>Hello <?=$name?>!</h1>

    <?php if($coinFlip): ?>
        <h1>Kull</h1>
    <?php else: ?>
        <h1>Kiri</h1>
    <?php endif ?>

    <ul>
        <?php for($i=0;$i<10;$i++): ?>
            <li><?=$i?></li>
        <?php endfor ?>
    </ul>
</body>
</html>
```

**Two new pieces of syntax:**

| Syntax | Meaning |
|---|---|
| `<?=$name?>` | Short echo: shorthand for `<?php echo $name; ?>` |
| `if(…):` … `endif` | **Alternative syntax**: a colon instead of `{`, and `endif` / `endfor` / `endforeach` instead of `}` |

**Why the alternative syntax:** with HTML in between, a closing `}` is very hard to match up by
eye. `<?php endfor ?>` tells you exactly what ended. Same logic as before, only the punctuation
differs.

`rand(0, 1)` gives a random 0 or 1, so the coin flip changes on every refresh: a neat
demonstration that the page is **generated per request**, not a static file.

**To view it:**
```bash
php -S localhost:8000
```

## ✅ Takeaways

1. **`__construct(private $w)` declares, sets visibility and assigns** in one line.
2. **Magic methods fire on events**: missing property, missing method, string conversion,
   destruction.
3. **`static` belongs to the class**, reached with `::`. `self::` is where it was written,
   `static::` is what it was called on.
4. **An interface is a contract.** Type-hint the interface, not the class, and implementations
   become swappable: including ones the original author never saw.
5. **A `.php` file is HTML with holes in it.** `<?= ?>` to print, `if: … endif` to stay readable.
6. **Pages are generated per request**: refresh and `rand()` gives a different answer.
